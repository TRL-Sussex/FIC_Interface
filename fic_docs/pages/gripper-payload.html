Gripper & Payload Mass

Most vendor URDFs describe the bare arm and omit the tool. The controller then compensates gravity for a robot that is lighter than the one in front of you — and the arm sags. How to detect it, fix it, and verify the fix on any robot.

The symptom you will actually see

A joint slowly falls under its own weight in impedance, and in joint admittance a joint drifts or oscillates instead of holding. It is worst on the joints carrying the most gravity load, and absent on joints that carry none — that pattern is the fingerprint. It is not a tuning problem, and adding damping only hides it.

Why it happens

fic_control computes its gravity feedforward from the URDF, once per control tick:

gravity_torques_ = solver_->gravity(q_current_);   // fic_control.cpp

That is the only producer of gravity_torques_ on hardware. Impedance adds it straight to the output torque; admittance passes it in as desired_effort. Either way, whatever the URDF fails to describe is weight the controller never holds up.

Vendor URDFs routinely stop at the tool flange. The shipped Kinova Gen3 URDF ends at ee_link with mass="0" and contains no Robotiq gripper at all — 1.339 kg of real hardware that the model simply does not know about.

Worse, the error is pose-dependent, so it cannot be trimmed away with an offset. Measured on a Kinova Gen3 with a Robotiq 2F-85:

Joint (0-based)0123456
Gravity shortfall (Nm)0.006.830.035.250.052.630.09

Joints 1 and 3 — shoulder and elbow — were the two that misbehaved. Joint 2, short by 0.03 Nm, was fine. Worst case across the workspace was 12.98 Nm.

Why admittance suffers more than impedance

An admittance controller integrates torque into position. A constant bias above the admittance_deadbands.joint_tau floor (2.0 Nm on the Kinova) is therefore fed in continuously and the joint walks. On the arm above, the 5.25 Nm elbow shortfall sat well clear of that deadband; correcting gravity dropped it to roughly 0.5 Nm, below the deadband, and the drive disappeared. Raising damping slows a runaway — it does not remove its cause.

Step 1 — Measure the shortfall on your robot

Do not guess whether this affects you. If your robot has a MuJoCo model that does include the tool (most in menagerie/ do), compare the two directly:

source fic_ws/install/setup.bash
python3 - <<'EOF'
import sys, numpy as np
sys.path.insert(0, 'fic_ws/src/fic_contact')
from fic_contact.residual import ArmModel, tool_payload_from_mjcf

URDF = 'fic_ws/src/menagerie/model/<ROBOT>/URDF/<ROBOT>.urdf'
MJCF = 'fic_ws/src/menagerie/model/<ROBOT>/xml/scene.xml'
JOINTS = ['Actuator1', 'Actuator2']          # your robot's joint_names, in order

mass, com = tool_payload_from_mjcf(MJCF, JOINTS)
print('tool the URDF is missing: %.4f kg at %s' % (mass, np.round(com, 5).tolist()))

bare   = ArmModel(URDF, JOINTS)
tooled = ArmModel(URDF, JOINTS, tool_payload=(mass, com))
rng = np.random.default_rng(0)
worst = max(float(np.max(np.abs(tooled.gravity(q) - bare.gravity(q))))
            for q in rng.uniform(-2.5, 2.5, (200, len(JOINTS))))
print('worst uncompensated gravity across 200 poses: %.2f Nm' % worst)
EOF

Anything above your mode's joint_tau deadband will drive an admittance joint. Anything above roughly 1 Nm is worth fixing for impedance too.

Step 2 — Build a gripper variant of the URDF

Copy the base URDF alongside the original, suffixed _gripper, and give the tool link a real <inertial>. A point mass is exact for gravity, which depends only on mass and centre of mass — the rotational inertia matters only to M(q) and Coriolis terms, which the gravity feedforward does not use.

<link name="ee_link">
  <inertial>
    <origin xyz="-0.006848 0.0 0.016310" rpy="0 0 0" />
    <mass value="1.3391" />
    <inertia ixx="4180E-6" ixy="0" ixz="0" iyy="5080E-6" iyz="0" izz="1250E-6" />
  </inertial>
</link>
The centre of mass must be in the tool link's own frame

tool_payload_from_mjcf returns the com in the last actuated link's frame. If you attach the mass to a different link, transform it. On the Kinova the end_effector joint rotates π about X and offsets −0.061525 m in Z, which turns [-0.00685, 0, -0.07783] in Bracelet_Link into [-0.00685, 0, 0.01631] in ee_link. Getting this wrong puts the weight on the wrong side of the wrist and makes the sag worse, not better.

Check for malformed inertia attributes while you are in there

The shipped Kinova URDF had ixx="4180E-6  " — with trailing whitespace. urdf_parser rejects the value and silently discards the entire <inertial> block, logging only "inertia element ixx is not a valid double". If you see that line at startup, a link you think is modelled is not.

Step 3 — Let has_gripper select it

Add the variant path next to the base one in fic_library/config/robots_config.yaml:

MyRobot:
  urdf_path: menagerie/model/MyRobot/URDF/MyRobot.urdf
  urdf_path_gripper: menagerie/model/MyRobot/URDF/MyRobot_gripper.urdf
  has_gripper: true

RobotConfigLoader swaps them once, at load:

if (config.has_gripper && !config.urdf_path_gripper.empty()) {
    config.urdf_path = config.urdf_path_gripper;
}

Because the swap happens at load rather than at each use, every consumer of urdf_path sees the arm as it physically is — gravity, IK, Jacobians and the workspace guard alike. Robots with no urdf_path_gripper are unaffected, so the field is safe to leave out.

Take the gripper off, set has_gripper: false, and the model reverts to the bare arm with no other edit.

Step 4 — Verify against an independent model

Do not trust the frame transform by eye. Score the new URDF against the MuJoCo model, which describes the same robot independently:

python3 - <<'EOF'
import sys, numpy as np
sys.path.insert(0, 'fic_ws/src/fic_contact')
from fic_contact.residual import ArmModel, link_inertials_from_mjcf

BASE, GRIP = '<base>.urdf', '<base>_gripper.urdf'
MJCF, JOINTS = 'scene.xml', ['Actuator1', 'Actuator2']
truth = ArmModel(BASE, JOINTS, link_inertials=link_inertials_from_mjcf(MJCF, JOINTS))
rng = np.random.default_rng(0)
for name, path in (('base', BASE), ('gripper', GRIP)):
    m = ArmModel(path, JOINTS)
    worst = max(float(np.max(np.abs(m.gravity(q) - truth.gravity(q))))
                for q in rng.uniform(-2.5, 2.5, (200, len(JOINTS))))
    print('%-8s worst error vs MJCF: %.3f Nm' % (name, worst))
EOF

On the Kinova this reported 12.983 Nm → 1.194 Nm, removing 91% of the error. The residual is the arm links' own inertials, which a tool payload cannot fix; if you need that last part, rebuild every link from the MJCF with link_inertials_from_mjcf as fic_contact does.

What changes when you restart

AreaEffect
Impedance modes (1, 2, 5, 6)The arm holds its pose instead of sagging, and feels lighter. Gravity is added directly to the output torque.
Joint admittance (3, 4)Joints stop drifting once their bias falls below joint_tau. Re-tune damping after this, not before — damping raised to mask the bias will now feel far too heavy.
Contact estimationfic_contact already corrects this independently via link_inertials_from_mjcf, so it is unaffected.

A rebuilt fic_control is required (the loader is a header), and the controller reads the URDF when the robot model is loaded, so restart the hardware stack.
