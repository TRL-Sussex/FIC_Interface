Installation (macOS / Apple Silicon)

Native simulation install via RoboStack + a CPU MuJoCo backend — no Linux binaries, no CUDA.

One command on any supported OS

bash install.sh at the repo root detects your platform and runs the right installer — the RoboStack flow on this page on macOS, or the one-click apt flow on Ubuntu 22.04/24.04. Everything below still applies; install.sh is just the front door.

What runs on macOS

The full FIC Studio GUI and MuJoCo simulation run natively on Apple Silicon. ROS 2 comes from RoboStack (conda-forge), and simulation uses the same CPU MuJoCo simulator as on Linux (mujoco_native), built on the official mujoco wheel. Real-hardware drivers (Franka libfranka, Kinova Kortex, VR/ZED, RealSense) remain Linux-only and are not built here — this is a simulation build. For hardware, use the Linux install.

Prerequisites

RequirementDetail
macOS13+ on Apple Silicon (arm64)
HomebrewOptional: used for Miniforge when it is installed
Disk~10 GB free (ROS 2 + toolchain)
Repo locationNot under ~/Documents, ~/Desktop, or ~/Downloads — see the warning below. Use e.g. ~/FIC_Interface.

Everything else — Miniforge (conda), the ROS 2 environment, Pinocchio, MuJoCo, PyQt5, the compiler toolchain, and the workspace build — is installed by the one-command installer.

Don't clone into ~/Documents, ~/Desktop, or ~/Downloads

macOS privacy protection (TCC) blocks app bundles launched from Finder/Launchpad from reading files in those folders. Because FIC Studio ships as a double-clickable .app that reads the workspace at launch, a repo in a protected folder makes the app bounce in the Dock and immediately quit (Terminal launches still work, which is why it's easy to miss). Keep the repo somewhere else — the home root (~/FIC_Interface), ~/dev/…, etc. The installer refuses to run from a protected folder and tells you how to move it. If you must relocate an already-built repo, move it and re-run the installer — colcon bakes absolute paths, so a clean rebuild is required.

Quick Install

cd ~/FIC_Interface               # NOT ~/Documents — see the warning above
zsh fic_install/macos/install-fic-studio-macos.sh

The installer is idempotent (safe to re-run) and never uses sudo — all installs are user-scoped (conda, and Homebrew if present). Override the repo location with FIC_ROOT=/path/to/FIC_Interface zsh … if you run it from elsewhere.

What the installer does

StepAction
1Uses Homebrew if it is installed (it is not required)
2Installs Miniforge (conda/mamba) if absent, through Homebrew when there
3Creates the fic_ros conda env with ROS 2 Humble from the robostack-staging + conda-forge channels
4Installs deps into the env: compilers, cmake, colcon, ament-cmake, Eigen, TinyXML2, yaml-cpp, Pinocchio, PyQt5 with QtWebEngine, pyqtgraph, numpy≥2, SciPy, cryptography, matplotlib, mujoco≥3.3, setuptools<80
5Builds the whole workspace (communication, menagerie, fic_simulation, fic_studio, mujoco_native, …)
6Builds real .app bundles — FIC Control Studio.app and FIC Dev Console.app — in ~/Applications (with the FIC icon, rendered from the SVG), so they appear in Launchpad, Spotlight and the Dock. Also drops .command launchers as a terminal-visible fallback
Cartesian control needs Pinocchio

The installer installs Pinocchio from conda-forge, so Cartesian IK/FK and virtual-wall features work. The build log confirms "pinocchio found". Without it, robots run in degraded joint-space-only mode (see Control Modes).

Distributable installer (.dmg)

To give FIC Studio to someone who doesn't have the repo cloned, build a downloadable disk image:

zsh fic_install/macos/build-macos-dmg.sh
# -> fic_install/macos/dist/FIC-Studio-Installer.dmg

The .dmg bundles the repo source only (not the ~4.5 GB conda env — dependencies are still downloaded at install time, so a network connection is required). The recipient mounts it and double-clicks Install FIC Studio.command, which:

StepAction
1Asks where to install (default ~/FIC_Interface) and refuses a protected folder (~/Documents/~/Desktop/~/Downloads)
2Copies the source there (a DMG is read-only, and the workspace must be built into a writable location)
3Runs install-fic-studio-macos.sh in a Terminal, so the multi-GB download shows live progress
Gatekeeper on a downloaded .dmg

A downloaded image is quarantined, so the first double-click of Install FIC Studio.command may be blocked — right-click → Open → Open once. The generated apps are ad-hoc signed for a smoother first launch.

First launch & Gatekeeper

The apps are unsigned ad-hoc bundles built locally by the installer (not downloaded), so Gatekeeper generally allows them. If macOS ever blocks one, right-click the app → Open once to whitelist it. The app's icon is generated from fic_install/fic-control-studio.svg; if you don't see it immediately, it's a Finder icon-cache delay — the installer already nudges LaunchServices to refresh.

Use setup.zsh, not setup.bash

The macOS default shell is zsh, and the ROS setup.bash relies on bash-only features — sourcing it under zsh silently fails to overlay the workspace, so mujoco_native won't be found. Always source install/setup.zsh. (The generated .command launchers already do this.)

In the GUI: pick KinovaGen3_7DOF or Franka_FR3, press SIM (a MuJoCo viewer window opens via mjpython) and FIC, then choose a control mode and drive the arm with the joint sliders or Cartesian inputs. Settings → Simulation shows "MuJoCo (native CPU, macOS)", selected automatically. Continue with the Quickstart and First Motion guides.

Manual Installation (Advanced)

If you prefer to run the steps yourself instead of the installer script:

# 1. Miniforge (conda) via Homebrew
brew install --cask miniforge
conda init zsh   # then restart the shell

# 2. RoboStack ROS 2 Humble env
conda config --env --set channel_priority flexible
mamba create -n fic_ros -c conda-forge -c robostack-staging ros-humble-desktop
conda activate fic_ros

# 3. Build + sim + FIC dependencies
mamba install -c conda-forge -c robostack-staging \
    compilers cmake ninja pkg-config colcon-common-extensions \
    ros-humble-ament-cmake eigen tinyxml2 yaml-cpp pinocchio \
    pyqt pyqtgraph 'numpy>=2' pyyaml 'mujoco=3.15.0' 'setuptools<80'

# 4. Build the simulation packages (or the whole workspace: drop --packages-select)
cd fic_ws
colcon build \
    --packages-select communication menagerie fic_simulation fic_studio mujoco_native \
    --cmake-args -DPython3_EXECUTABLE=$CONDA_PREFIX/bin/python
source install/setup.zsh
Use numpy≥2 (not <2)

RoboStack's ros-humble on osx-arm64 is built against NumPy 2.x (its std_msgs cmake references numpy/_core/include). Pinning numpy<2 makes the communication package fail to configure. This is the opposite of the Linux install's numpy<2 pin.

Pin setuptools<80, and don't use --symlink-install

setuptools 80 removed the legacy setup.py develop/--editable/--uninstall commands that colcon's ament_python build (and the GUI's Rebuild buttons) rely on — with a newer setuptools, builds error out. Pin setuptools<80. For the same reason --symlink-install is not used on macOS; the packages are copy-installed, and fic_studio resolves the repo root from the fic_ws path component so it works either way.

Rebuilding

After code changes, use Settings → Developer → Rebuild Workspace in the GUI, or from the activated env:

colcon build --packages-select fic_studio \
    --cmake-args -DPython3_EXECUTABLE=$CONDA_PREFIX/bin/python

See Build Tools for the in-GUI build dialogs.

Troubleshooting

ProblemFix
ros2 / colcon: command not foundThe env isn't active. Run conda activate fic_ros (the .command launcher does this for you)
mujoco_native package not foundSource the workspace with source install/setup.zsh (zsh) — not setup.bash
communication fails, referencing numpy/_core/includeYou have numpy<2. Run mamba install -n fic_ros 'numpy>=2'
Build errors: --editable / --uninstall not recognizedsetuptools is too new. Run mamba install -n fic_ros 'setuptools<80'
SIM / Rebuild buttons fail with a path like install/fic_studio/fic_wsRebuild the workspace (this build carries the fixed repo-root resolution). The launchers also export FIC_ROOT as a guard
The app appears in ~/Applications but bounces in the Dock and quitsThe repo is under a privacy-protected folder (~/Documents/~/Desktop/~/Downloads) and the app can't read the workspace. Move the repo out (e.g. ~/FIC_Interface) and re-run the installer. Terminal / .command launches are unaffected.
First launch blocked: "unidentified developer"The .app is ad-hoc signed locally. Right-click the app → Open once to whitelist it (double-click works thereafter).
MuJoCo viewer won't openThe viewer needs mjpython (bundled with the mujoco wheel); the launch file uses it automatically. Pass headless:=true to run without a window
No timeout command when scriptingmacOS lacks it — use gtimeout (brew install coreutils) or perl -e 'alarm N; exec @ARGV'
