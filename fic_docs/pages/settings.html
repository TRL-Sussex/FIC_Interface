Settings

Stored in ~/.robot_selector_gui_settings.yaml — v5.6.0

Accessing Settings

Open Settings from the sidebar (or press Ctrl+5). Settings are displayed as a single scrollable column of collapsible cards; every card starts expanded and can be collapsed by clicking its uppercase header. The title row holds a sticky SAVE SETTINGS / DISCARD button pair plus a ? Help button that opens the Help panel. Clicking Save writes all changes to ~/.robot_selector_gui_settings.yaml and applies them (theme, font, tolerances, shortcuts, log-viewer layout). Clicking Discard reverts every widget — including a live theme preview — to the snapshot taken when the page was opened; the YAML file is not touched. Cards marked ⚠ Restart required take effect only on the next application launch.

Station ID is not here

Station ID is managed from the toolbar Robot selector (Robot 1–4, or Master for a PC with no arm), not from Settings. Changing it there shows a confirmation dialog, writes general.station_id to the YAML and restarts the app (os.execv) to re-point its ROS topics to robot{N}_* (a Master: a number of its own, 100–999). The selector is disabled while a session is running.

Settings Lifecycle

The same YAML file is read at two different times: once by entry_pro.py before ROS is initialised (domain ID and station ID), and once by the GUI's SettingsMixin, which merges it with DEFAULT_SETTINGS so missing keys always get sane defaults.

Appearance

Controls the theme and the application font. They apply the moment you press Save, in the classic window and in every open web UI (no reload, no restart). Clicking a theme button only selects it until then.

A theme is two independent choices — a palette (Warm or Cool) and a brightness (Dark or Light) — giving four themes from two short button groups rather than one button per theme.

PaletteReads as
WarmBrowns and ambers. The original FIC Studio look, and still the default.
CoolSlate and blues.
Warning colours never change

Whichever palette is chosen, warning stays amber and danger stays red — the emergency stop is drawn with them. Cooling a stop button to match the theme would be a safety regression, not a preference. Body text is checked against every surface in all four themes to WCAG AA (4.5:1) by an automated test, not by eye.

SettingDefaultOptions
themewarmth_darkOne of warmth_dark, warmth_light, cool_dark, cool_light — written as <palette>_<brightness> from the two button pairs. Legacy dark/light values in old YAML files are normalized on load, and an unrecognised name falls back to warmth_dark rather than failing.
font_familyConsolasConsolas, Courier New, Segoe UI, Arial, Roboto Mono
font_size128–18 px

Font changes call QApplication.instance().setFont(QFont(family, size)) on Save so the new font is applied immediately without a restart.

Network ⚠ Restart required

Changing ros_domain_id requires restarting the application. The amber ⚠ Restart required pill on this card indicates that. The new domain ID takes effect on the next launch; entry_pro.py reads it from the YAML before rclpy.init().

SettingDefaultDescription
ros_domain_id0ROS 2 DDS domain ID (0–232). Both machines must match for teleoperation. Takes effect on next launch.
partner_ip—IP address of the teleop partner machine (for unicast DDS)
dds_modeMulticast (Auto)Multicast (Auto) or Unicast (Manual IP); stored as multicast/unicast
⚠️ Environment variable wins

entry_pro.py only exports ROS_DOMAIN_ID from the YAML when the variable is not already set in the environment. If your .bashrc or launch script exports it, that value overrides the Settings page.

The Network card also includes a Generate cyclonedds.xml button. It requires Partner IP to be filled in, then writes a CycloneDDS peer-discovery configuration to ~/cyclonedds.xml listing your own IP and the partner IP as unicast peers. After generating, export it before launching ROS nodes:

export CYCLONEDDS_URI=file://$HOME/cyclonedds.xml

See Teleoperation for the full two-machine setup.

Simulation

Selects which physics engine the SIM button launches. The dropdown offers MuJoCo (CPU, stable) and Newton (NVIDIA Warp, GPU). See Simulation → Simulator Backends for runtime details and known limitations.

SettingDefaultOptions
backendresolved at runtime*mujoco_native (CPU) or newton (NVIDIA Warp GPU)

* The default is newton when both of these are true:

  1. The marker file ~/.fic_studio_install_hints.yaml exists. install-deps.sh writes it (content newton_available: true) only when an NVIDIA GPU was detected via nvidia-smi and import newton succeeded after the pip install.
  2. import newton still succeeds now (i.e. the package is still installed).

Otherwise the default is mujoco_native. Once a value is saved to ~/.robot_selector_gui_settings.yaml, it always wins over the auto-detected default. A file saved before v4.5.0 may say backend: mujoco (the retired C++ simulator); it loads as mujoco_native, as does any other value except newton.

The Newton dropdown entry is greyed out if the package is not installed

The Settings card probes importlib.util.find_spec('newton'). If Newton was uninstalled, the entry shows "Newton (not installed — run install-deps.sh)" and cannot be selected.

Switching backends does not restart anything automatically. If a simulation is already running, stop it (SIM off), change the setting, and start it again — the new backend will launch.

Playback Tolerances

Used by Sequences and Teach Mode to decide when a waypoint is "reached":

SettingDefaultRangeDescription
joint_tolerance_deg3.0°0.5–20.0°Joint angle threshold for "position reached"
position_tolerance_mm5.0 mm1.0–50.0 mmEnd-effector distance threshold for Cartesian targets
timeout_seconds30.0 s5.0–120.0 sMaximum wait time per waypoint before skipping

On Save the values are converted for the sequence engine: degrees to radians and millimetres to metres. The YAML always stores the human-readable degree/millimetre values.

Shortcuts

This card lists the rebindable keyboard shortcuts as plain text fields — click a field and type the key combo (e.g. Ctrl+R). Changes apply on Save, which re-registers the shortcuts. Stored under the shortcuts: section of the YAML.

* These three accelerators are owned by the menu bar (File ▸ Save, View ▸ Show Log Panel, View ▸ Tuning Panel) and are intentionally not re-registered by the Settings system, to avoid ambiguous-shortcut double firing. Fixed application keys such as F1 (Help), F5/F6 (start Sim/FIC), F11 (fullscreen), Ctrl+B (Compile Workspace) and Ctrl+/ (shortcut reference) live in the menus and are not rebindable here. See Keyboard Shortcuts for the complete list.

🛑 Space is the keyboard E-STOP

Pressing the estop shortcut stops running sequences, scripts and teach mode, kills the controller, driver, FIC and simulator processes, stops bag recording, and publishes each active robot's last-known joint pose as a lock target. See Emergency Stop.

Extensions ⚠ Restart required

Lists all discovered extensions found under Extensions/, each with an enable checkbox. Unlike the other cards, this one has its own APPLY button: clicking it writes the enabled list to extensions.enabled in the YAML immediately (no page-level Save needed) and then offers to restart the application right away (os.execv). If you decline, the change takes effect on the next launch. If nothing changed, APPLY reports "No changes to apply".

See Extensions for the full extension catalog and authoring guide.

Gamepad

Configuration for Xbox-compatible gamepad input. The GamepadMixin reads /dev/input/js* directly via the Linux joystick protocol, scanning at 2 Hz for hot-plug detection and publishing commands at 100 Hz. See Gamepad Control for the full control reference. The card contains five groups:

GroupContents
Tuningdeadzone spinbox — default 0.12, range 0.0–0.5, step 0.01. Stick deflection below this is ignored; the remainder is rescaled to full range.
Axis InversionCheckboxes to flip Left/Right Stick X and Y (LX, LY, RX, RY) individually. All off by default.
Button MappingPer-button action dropdown (Kinova-style defaults, e.g. A→home, B→e_stop, Back→toggle_space, X/Y→postural/elbow toggles).
Fixed ControlsReference only, not remappable: LT/RT = variable gripper, D-pad Up/Down = speed level, D-pad Left/Right = cycle robot.
Connected ControllersLive per-pad cards with axis readouts, held buttons, control state, and a target-robot dropdown (multi-robot stations).

Gamepad changes take effect immediately and — unlike the other cards — are written to the YAML (gamepad: section) as soon as you change them; they do not wait for the page-level Save.

Help

The Help content previously embedded as a 14-tab section inside Settings has been moved to the standalone Help panel. Press F1, click Help in the sidebar, or use the ? Help button in the Settings title row to open it.

Settings File

Settings are stored as YAML. On load the file is recursively merged with the built-in defaults, so missing keys are filled in for forward compatibility. A malformed file is not fatal: entry_pro.py prints a warning to stderr and falls back to defaults — fix or delete the file to recover your preferences. You can inspect or edit it directly:

nano ~/.robot_selector_gui_settings.yaml

Top-level sections and what writes them:

YAML keys are stable across v3.9.x; entry_pro.py reads network.ros_domain_id and general.station_id from this file before rclpy.init(), so do not rename those keys. Because auto-save is on by default, manual edits made while the GUI is running can be overwritten within the auto-save interval — edit the file with the GUI closed.
