Build Tools

Compile the ROS 2 workspace from the GUI or terminal.

In-App Build Dialogs

All build operations run in a modal build dialog (fic_studio.widgets.BuildDialog) with live output (ANSI colour codes stripped), an elapsed timer, and a Cancel button that kills the build process. No external terminal windows are spawned. On failure the dialog stays open so you can read the log.

ButtonCommandWhere
Rebuild Workspace (Ctrl+B)colcon build --symlink-installSettings → Developer card → Build row
Rebuild Package…colcon build --symlink-install --packages-select <pkg>Settings → Developer (picker lists directories under fic_ws/src)
Clean Rebuildrm -rf build install log then colcon build --symlink-installSettings → Developer (asks for confirmation first)
COMPILE DRIVERbuild_command run in build_directory from robots_config.yamlRobot Config page
Install APIpython3 -m pip install --break-system-packages -e <FIC_ROOT>/fic_apiScript Editor toolbar

Workspace builds run in the workspace path shown in Settings (editable via the Browse button next to it); by default this resolves to fic_ws under the repository root. The clean step of Clean Rebuild runs as a blocking pre-command with a 120 s timeout before colcon starts.

Manual Build from Terminal

# Source ROS 2
source /opt/ros/jazzy/setup.bash    # or humble/kilted

# Navigate to workspace (adjust if the repo lives elsewhere)
cd ~/FIC_Interface/fic_ws

# Build everything
colcon build --symlink-install

# Build a single package
colcon build --symlink-install --packages-select fic_studio

# Clean and rebuild
rm -rf build install log
colcon build --symlink-install

# Source the workspace after building
source install/setup.bash
Repo location

~/FIC_Interface is only a convention. The Studio resolves the project root by walking up from its own install location, and you can override it with the FIC_ROOT environment variable (see fic_studio/config.py). All paths below use ~/FIC_Interface as the example root.

First-Launch Auto-Build

The desktop launchers fic_install/fic-control-studio.sh and fic-dev-console.sh build the workspace automatically if fic_ws/install/setup.bash is missing. They try a chain of progress UIs in order:

OrderUIRequires
1PyQt5 dialog (build_gui.py)PyQt5
2tkinter dialog (installer_gui.py)tkinter
3zenity --progresszenity
4Plain terminal colcon build—

build_gui.py can also be run by hand: python3 fic_install/build_gui.py <work_dir> <command> [--title T] [--pre-command CMD]. Exit codes: 0 success, 1 failed, 2 cancelled, 3 GUI could not start. On success it auto-closes after 2 seconds; failures stay open. The launcher auto-detects the ROS distro from $ROS_DISTRO or the newest entry in /opt/ros/. See Installation.

Compiling Robot Drivers

Each robot in fic_library/config/robots_config.yaml can define a build_directory and build_command (edit them in Robot Configuration → Edit → Build tab). The COMPILE DRIVER button runs the command in that directory inside a build dialog; multi-line commands are joined with &&. Template variables {robot_lib} (the robot_library directory) and {robot_name} are substituted first. If the build directory does not exist you are offered to create it.

# Franka FR3 (shipped defaults)
build_directory: '{robot_lib}/libfranka/build'
build_command:   cmake -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/opt/openrobots .. && cmake --build .

# Kinova Gen3 (shipped defaults)
build_directory: '{robot_lib}/Kinova/api_cpp/examples'
build_command:   ./scripts/build-gcc.sh

Manual Process Launch Commands

These are the commands that the GUI toolbar buttons execute (see Processes). Use them in a terminal if you prefer manual control or need to debug. <sid> is the station id (1 for a single-robot setup).

MuJoCo Simulation (SIM button)

source ~/FIC_Interface/fic_ws/install/setup.bash
ros2 launch mujoco_native simulation_launch.py robot_name:=Franka_FR3 station_id:=1

The simulator runs on the mujoco Python wheel, so no library path is needed (add headless:=true for no viewer). When the Newton (GPU) backend is selected in Settings, the GUI launches mujoco_newton instead:

ros2 launch mujoco_newton simulation_launch.py robot_name:=Franka_FR3 station_id:=1

The GUI captures simulator output to /tmp/fic_sim_<pkg>_<timestamp>.log (the path is printed in the Logs) — check it if the SIM button toggles on but no window appears. If mujoco_newton is not built (fic_ws/install/mujoco_newton missing) the GUI logs a warning and falls back to the CPU simulator (mujoco_native). See Simulation for backend details.

FIC Simulation Controller (FIC button, simulation mode)

source ~/FIC_Interface/fic_ws/install/setup.bash
ros2 launch fic_simulation fic_launch.py robot_name:=Franka_FR3 num_joints:=7 \
    station_id:=1 source_prefix:=robot1_simulation

source_prefix selects the joint-state source: robot<sid>_simulation for the simulator, or vr when driven by the VR relay.

FIC Hardware Controller (FIC button, hardware mode)

source ~/FIC_Interface/fic_ws/install/setup.bash
ros2 launch fic_hardware robot_control_launch.py robot_name:=Franka_FR3 station_id:=1

Robot Driver / API (API button)

The driver command is configured per robot in robots_config.yaml under driver_command (Robot Configuration → Edit → File Paths tab). Template variables {robot_lib} and {robot_name} are replaced automatically, and the GUI exports FIC_ROOT into the driver's environment. Shipped defaults:

# Franka FR3:
cd {robot_lib}/libfranka/build && ./examples/cartesian_impedance_control 172.16.0.2

# Kinova Gen3:
cd {robot_lib}/Kinova/api_cpp/examples/build-gcc-release && ./01-torque-control_00-Torque_Controller

Driver stdout is streamed into the GUI log panel (consecutive identical lines are collapsed into a “repeated ×N” entry). If the driver exits on its own, the log shows Driver exited (code N) and the API button resets so you can restart it.

ROS Bag Recording (BAG button)

The GUI records into <FIC_ROOT>/experiments/bags/ with an auto-incremented session name (YYYY_MM_DD_session_NNN):

source ~/FIC_Interface/fic_ws/install/setup.bash
ros2 bag record -a -o ~/FIC_Interface/experiments/bags/$(date +%Y_%m_%d)_session_001

Bag Replay (REP button)

Replays the bag recorded in this session, or the most recent bag in experiments/bags. Recording must be stopped first.

source ~/FIC_Interface/fic_ws/install/setup.bash
ros2 bag play ~/FIC_Interface/experiments/bags/2026_04_12_session_001

Plotter (PLT button)

source ~/FIC_Interface/fic_ws/install/setup.bash
ros2 run fic_simulation plotter_node.py --ros-args -p station_id:=1 -p num_joints:=7

FIC Control Studio GUI

source ~/FIC_Interface/fic_ws/install/setup.bash
ros2 run fic_studio fic_studio_pro       # Full Studio
ros2 run fic_studio fic_dev              # Dev Console

Symlink Install

The --symlink-install flag creates symlinks instead of copying files for Python packages. This means you can edit Python source files and see changes immediately without rebuilding — only C++ packages require a rebuild after code changes.

Newton backend needs both pip and colcon

The Newton GPU backend has two halves: the pip packages (newton, mujoco-warp, warp-lang, pyglet — installed by fic_install/install-deps.sh as newton[sim,importers] when an NVIDIA GPU is detected) and the mujoco_newton ROS package, which must be built with colcon build. If either is missing, the SIM button silently falls back to the CPU simulator with a warning in the log.

Troubleshooting Builds

ProblemFix
Build fails with missing headerInstall the missing system dependency via apt (or re-run fic_install/install-deps.sh)
Build fails with empy errorpip install empy==3.3.4 (v4.x breaks colcon)
Package not found after buildRun source install/setup.bash after building
Stale build artefactsUse Clean Rebuild (deletes build/install/log folders)
Build succeeds but changes not visibleFor C++ changes, rebuild. For Python with symlink-install, restart the node.
Newton selected but MuJoCo startscolcon build --packages-select mujoco_newton, then restart the sim
SIM button on, no simulator windowRead /tmp/fic_sim_*.log (path is logged when the sim starts)
Rebuild buttons point at wrong workspaceFix the workspace path in Settings (Browse button)
