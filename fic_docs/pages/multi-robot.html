Multi-Robot

Every Studio on the network on one page: see each robot, stop them all, pair them for teleoperation.

Overview

A lab runs one FIC Control Studio per robot PC, each on its own station, all on one ROS domain (see Multi-PC Lab Setup). The Multi-Robot page finds the other Studios by itself — there is nothing to add by hand — and has three parts:

PartWhat it is for
FleetA card for every Studio on the network, with E-STOP ALL and PAUSE ALL.
TeleoperationMake one station's arm follow another's. See Teleoperation.
ControlThe Simulation / Hardware / VR switch, Home, Reset and Send for the robot the control bar drives.

Stations: Robot 1–35 and Master

The toolbar's Robot selector sets this Studio's station. It restarts the Studio to re-point its topics.

StationTopicsFor
Robot 1…35robot1_*…robot35_*The PC wired to that robot. PC N is Robot N.
MasterrobotNNN_* (100–999, from the PC name)The control seat, e.g. a lab's control PC. It has no arm of its own: it watches and commands the fleet, Any number of PCs can be Master at once: each takes its own number, so their simulations never meet each other or a real arm.
One Studio per station

Two Studios on the same station both command the same robot. The Fleet section shows a red warning naming both machines when that happens. A PC that has never run the Studio starts as Robot 1, so set the station before the first real run.

Neighbours

Robot stations stand in a line, like benches in a teaching lab: a robot Studio shows and pairs with its neighbours, the station on its left (N−1) and on its right (N+1). Robot 1 has only Robot 2 beside it, and Robot 35 only Robot 34. The Fleet section and the teleoperation form list your own card and those neighbours (and any Masters); a robot refuses to follow a robot that is not its neighbour. A Master sees the whole lab and may pair any two stations. Up to 35 robot Studios share one network and one ROS domain this way.

Fleet

Every Studio announces itself about once a second. A Studio that has not been heard from for 3.5 s drops off the page. Each card shows:

  • the station, and this Studio on your own card;
  • the host name, the robot, and whether it runs in SIM, on HARDWARE or in VR;
  • its state:
    • running: a session is started;
    • live: joint data is flowing;
    • idle: neither;
  • its control mode;
  • any teleop pairing: leads Robot 3, or follows Robot 1 (holding when the leader's data has paused).
ButtonDoes
DrivePoints this Studio's control area at that station, so the control bar commands it. If that arm is on hardware, you are asked to confirm first. Your own card has no Drive button.
WebOpens that Studio's web remote in a browser.
E-STOP ALLE-stops every Studio on the network, this one included, through each Studio's own E-stop path. Each E-stop halts its controller, then its processes.
PAUSE ALLSends Pause Controller to every station. It only affects hardware.
Not a safety-rated stop

E-STOP ALL travels over the network. It needs the network and the receiving Studio to be up. Each robot's own E-stop remains the primary stop.

Driving another station

Drive adds that station's publishers to this Studio, but it does not subscribe to that station's 1 kHz state topics. Streaming them across the network would load DDS and that robot's control loop. The control area can therefore command the station, but it shows no live joint values for it.

Teleop lock

The toolbar's Teleop checkbox disables this Studio's local commanding, so its robot can only be driven from outside: another Studio, teleoperation, VR or a gamepad. E-STOP always stays live.

For developers

  • fic_studio.fleet.presence: the presence cards. Topic /fic/fleet/presence (std_msgs/String, JSON).
  • fic_studio.fleet.commands: lab-wide commands. Topic /fic/fleet/command, commands estop and pause. Each command carries an id, so it runs once.
  • fic_studio.fleet.stations: station numbers and labels. The setting MASTER = 0 becomes a per-PC station (master_station(host)).
  • fic_studio.mixins.fleet_mixin: the page sections.

The core modules are Qt-free and are tested without a network (test/test_fleet.py).

card_robot_type() and _card_topic_rid() (multi_robot_mixin) remain available for extensions.
