Installation (Linux / Ubuntu)

One-click installer or manual setup, for Ubuntu + ROS 2.

One command on any supported OS

bash install.sh at the repo root detects your platform and runs the right installer — the flow on this page on Ubuntu 22.04/24.04, or the RoboStack setup on an Apple Silicon Mac. Everything below still applies; install.sh is just the front door. Everything it installs or creates, per platform, and how to remove it: fic_install/WHAT-GETS-INSTALLED.md in the repository; bash install.sh --dry-run shows the plan without changing anything.

This is the Linux/Ubuntu install — not compatible with macOS

Everything on this page (the Install_FIC_Studio.desktop installer, apt/pkexec package installs, /opt/ros sourcing, .desktop launcher registration, and the NVIDIA/Newton GPU backend) is Ubuntu-only and will not work on macOS. On macOS there is no apt, no system ROS 2 under /opt/ros, and the Linux installer's apt/desktop steps do not apply. On an Apple Silicon Mac, follow Installation (macOS) instead, which uses RoboStack (conda-forge ROS 2) and a native CPU MuJoCo backend.

The installer handles everything else

ROS 2 itself, the system, ROS 2 and Python packages, the workspace build and the launcher entries. The repository can live at any path — the installer resolves everything relative to its own location, and the launch scripts honour a FIC_ROOT environment variable if you need to override the auto-detected repo root.

Quick Install

git clone https://github.com/TRL-Sussex/FIC_Interface.git ~/FIC_Interface
cd ~/FIC_Interface
bash install.sh

install.sh hands over to Install_FIC_Studio.desktop on Ubuntu. That is the installer — a bash script with a .desktop extension so it can also be double-clicked from the file manager (right-click → Properties → Permissions → Allow executing as program first). When double-clicked it relaunches itself detached from the terminal and drives everything through themed dialogs.

Options

All optional — the installer asks for anything not given on the command line.

FlagDoes
--yes, -yAccept every default and ask nothing, for terminals and scripts. Keeps the window, so existing scripted installs are unchanged.
--headlessThis machine shows no window; the Studio is used from a browser on another PC.
--with-guiThis machine shows a window (the default).
--dry-runReport what would be installed; change nothing.

A window, or headless

The installer asks how this machine should show the Studio. It is asked at install time because it belongs to the machine rather than to a session: a robot with no monitor should never draw an interface, and one on a desk always should. Re-run the installer to change it, or pass --headless / --with-gui to set it without a prompt so a fleet can be installed without anyone clicking.

  • Window — the Studio opens its interface in its own Qt window.
  • Headless — it draws nothing at all: no Qt window, no QtWebEngine, no WebGL. It still runs its ROS node, joins the fleet and serves the web interface, so you work on it from a browser on another PC.

The answer lands in ~/.config/fic-studio/interface.conf as FIC_HEADLESS=1 or 0, and fic_install/fic-control-studio.sh turns it into QT_QPA_PLATFORM=offscreen — the mode the Studio already recognises (qt_webengine.HEADLESS_PLATFORMS). Setting QT_QPA_PLATFORM yourself still wins.

Choose headless for any machine without a monitor. Measured on a lab robot: windowed, fic_studio_pro took 121 % CPU with another 24 % in QtWebEngineProc; headless, 5.4 % and no QtWebEngine at all, with the web remote still answering and the station still announcing on the fleet. A screenless machine has no GPU path — X falls back to the dummy driver, Mesa to llvmpipe, and Chromium then blocklists WebGL, so Three.js renders in software on the CPU, on a machine whose other job is a 1 kHz control loop. A browser on a PC that has a GPU draws the same interface properly and costs the robot nothing.

What the installer does

StepAction
1Detects the machine (Ubuntu version, architecture, board, ROS 2, GPU) with fic_install/detect-system.sh
2Installs Python, pip and tkinter if they are missing (its dialogs need them)
3Installs ROS 2 (ros-base and ros-dev-tools) from the ROS apt repository if none is installed
4Finds and installs what is missing. apt: cmake, build-essential, colcon, git, Eigen, TinyXML2, yaml-cpp, Boost, GLFW, PyQt5 with QtSvg and QtWebEngine, PyYAML, NumPy, SciPy, cryptography, pyqtgraph, matplotlib, tkinter. ROS 2: rclcpp, std/geometry/sensor/nav messages, std_srvs, urdfdom headers, and Pinocchio (optional). pip: mujoco
5Checks that TinyXML2 is the one ROS links against (a second copy makes the controller crash at start-up)
6Checks that the web interface imports (a pip PyQt5 in ~/.local can break it, and the installer says how to fix that)
7With an NVIDIA GPU, offers the Newton GPU simulator (see below)
8Builds the workspace with ./build.sh (Release) in a progress window; if it is built already, offers Rebuild or Skip
9Builds the Kinova driver (amd64) and the inner-loop MCU tools
10Asks which app to install (Control Studio, Dev Console or both) and whether this machine shows a window or runs headless
11Adds the launcher entries to ~/.local/share/applications/

The dialogs use tkinter, in the web interface's dark theme (fic_install/installer_theme.py), falling back to zenity and then to terminal prompts. The workspace build shows a PyQt5 progress window (fic_install/build_gui.py).

Optional: MuJoCo Newton (NVIDIA GPU only)

If nvidia-smi succeeds during install, the installer offers to add NVIDIA's Newton physics backend (MuJoCo solver running on Warp/CUDA, ~141 MB) alongside the standard CPU MuJoCo. Accepting runs pip install --break-system-packages 'newton[sim,importers]==1.7.0' 'mujoco==3.15.0' 'pyglet>=2.0', which pulls the following pinned versions:

PackageVersionPurpose
newton1.7.0Physics engine API
warp-lang1.18.0 (≥ 1.17.0)NVIDIA Warp runtime (ships its own CUDA 12.x kernels)
mujoco-warp3.15.0 (~= 3.15.0)MuJoCo solver compiled to Warp
mujoco3.15.0 (~= 3.15.0)MJCF parser (shared)
trimesh≥ 4Mesh loading for STL/OBJ refs in MJCF
pyglet2.1.15 (≥ 2.0)OpenGL window for Newton's ViewerGL — without this Newton runs headless
Let the newton[sim] extra choose the mujoco / mujoco-warp versions

Each Newton release pins the MuJoCo pair it was built against (newton 1.7.0 → mujoco ~= 3.15.0 + mujoco-warp ~= 3.15.0). Don't upgrade pip mujoco past that pin while Newton is installed — a manual pip install -U mujoco to 3.16 breaks the GPU backend at runtime. The installer pins MuJoCo 3.15.0 for the CPU simulator too, so both simulators run the same physics. (Earlier pairs: newton 1.3.0 with MuJoCo 3.8, newton 1.1.0 with 3.6.)

Both simulators use the pip mujoco wheel

The CPU simulator (mujoco_native) runs on whichever pip mujoco is installed: 3.15.0 from the installer, with or without Newton, as in the Docker image. Until v4.5.0 the default Linux simulator was a C++ package that linked a vendored MuJoCo 3.10.0; it was retired.

On a successful Newton install the installer writes ~/.fic_studio_install_hints.yaml (newton_available: true). On first launch the Studio defaults the simulator backend to Newton only if that hint file exists and import newton succeeds; otherwise it defaults to the CPU simulator (mujoco_native). If the NVIDIA prompt is declined, or there is no NVIDIA GPU, the Studio runs the CPU simulator. The choice is also exposed in Settings → Simulation → Backend so it can be flipped after install. See Simulation for the runtime details and known Newton limitations, and Settings for where the backend selection is stored.

Which mode?

Use Control Studio on a development workstation with simulation. Use Dev Console on a PC next to the real robot for direct control and teleoperation. See FIC Dev Console for details. After installing, continue with the Quickstart and First Motion guides.

Uninstalling

rm ~/.local/share/applications/fic-control-studio.desktop
rm ~/.local/share/applications/fic-dev-console.desktop
rm -f ~/.fic_studio_install_hints.yaml
update-desktop-database ~/.local/share/applications

This only removes the launcher entries and the Newton hint file; the repo, workspace build, and installed apt/pip packages are left untouched.

Manual installation

With ROS 2 installed (Humble on 22.04, Jazzy on 24.04), install the dependencies and build:

cd ~/FIC_Interface
sudo bash fic_install/install-deps.sh          # optional argument: the ROS 2 distro
./build.sh
source fic_ws/install/setup.bash
ros2 run fic_studio fic_studio_pro

install-deps.sh installs a similar set of packages to the installer's (step 4 above; the exact lists are in fic_install/WHAT-GETS-INSTALLED.md), plus ros-dev-tools for colcon, and pip-installs mujoco for your user. On amd64, when the camera extensions are in the checkout, it also installs pyrealsense2 and mediapipe. With a working nvidia-smi it also installs Newton. It does not build the workspace or add launcher entries: ./build.sh builds, and bash fic_install/install-desktop-entry.sh adds the Studio's launcher entry.

QtWebEngine: use the apt package, not pip

The Studio's window shows the web interface, which needs QtWebEngine built against the system Qt: sudo apt install python3-pyqt5.qtwebengine (both scripts do this). Do not pip install PyQtWebEngine or PyQt5: a pip wheel in ~/.local shadows the system one and fails with an undefined symbol error. If you already did, run pip uninstall PyQtWebEngine PyQtWebEngine-Qt5 PyQt5 PyQt5-Qt5 PyQt5-sip. If QtWebEngine cannot load, the Studio offers the classic interface (also --classic).

numpy stays below 2

The pip installs ask for numpy<2: apt's matplotlib, SciPy, OpenCV and ROS are built against NumPy 1.x, and a NumPy 2 in ~/.local shadows theirs and breaks their imports. If you pip-install something that pulls NumPy 2 in, put it back with pip install --user 'numpy<2'.

Ubuntu 24.04 marks the system Python as externally managed

pip then refuses system-wide installs (PEP 668). The installer installs mujoco with --user --break-system-packages; install-deps.sh tries --user first and adds --break-system-packages only if pip insists. Either way the packages go into ~/.local, not the system Python.

Optional: Newton GPU backend

Only on machines with a working NVIDIA driver (check with nvidia-smi):

python3 -m pip install --user --break-system-packages 'newton[sim,importers]' 'pyglet>=2.0'
echo "newton_available: true" > ~/.fic_studio_install_hints.yaml
python3 -c "import newton, warp; warp.init(); print(newton.__version__)"

Building after a change

Run ./build.sh from the repository root (Release build; extra arguments go to colcon, e.g. ./build.sh --packages-select fic_studio). See Build Tools for rebuilding from inside the Studio.
