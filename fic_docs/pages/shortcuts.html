Keyboard Shortcuts

Quick reference for keyboard shortcuts in FIC Control Studio.

Shortcuts come from two places: menu-bar accelerators defined by the Full Studio window, and a small set of configurable bindings registered from your settings file (see Settings). Press Ctrl+/ (Help › Keyboard Shortcuts) at any time to open the same reference inside the app.

What Space actually does

The E-STOP shortcut is not just a process kill. It fans out an emergency-stop hook to every loaded extension (sequences, teach mode, scripts, teleop, …), commands control mode 0 to every active robot so the controller ramps torque down to a safe hold at the last-known joint pose, waits ~250 ms for the ramp, and only then tears down all processes. See E-STOP and Safety.

Sequences & Scripts

Ctrl+R (play sequence) and Escape (stop sequence) are registered as configurable bindings, but since the Sequences panel became an extension in v3.0 the sequence engine lives on the extension, not the main window — so these two bindings currently do nothing. Use the PLAY / STOP buttons on the Sequences panel instead. E-STOP (Space) does halt a running sequence, teach-mode recording, or script through the extension emergency-stop hook.

Customizing Shortcuts

Open Settings › Shortcuts, click a field, and type the new key combo (e.g. Ctrl+R). Bindings are stored under shortcuts: in ~/.robot_selector_gui_settings.yaml and re-registered when you save settings — no restart needed.

Fixed accelerators

save_settings, toggle_log, and panel_tuning appear in the Settings editor but changing them has no effect: those accelerators are hard-wired to the File and View menus to avoid ambiguous double-firing. All other menu shortcuts (F5–F9, Ctrl+H, Ctrl+B, …) are likewise fixed.

Keyboard Control: driving the arm

For anyone without a gamepad. Turn it on with View › Keyboard Control or Ctrl+K; the status bar then shows KBD and what the keys drive (CART, or the joint, e.g. J4). Hold a key to move; let go and the arm holds its target. The keys publish what the gamepad publishes, so the control mode must match the space: Cartesian keys need a Cartesian mode, joint keys a joint mode (the log says when they disagree).

KeyAction
W / SForward / back (Cartesian)
A / DLeft / right (Cartesian)
Q / EUp / down (Cartesian)
J / LYaw (Cartesian)
1–9Pick a joint (switches to joint space)
↑ / ↓ (or , / .)Move the picked joint
TabSwap joint / Cartesian space
O / COpen / close the gripper
Shift / Ctrl heldThree times faster / a quarter of the speed

While it is on, the Studio window's mode keys need Shift: Shift+J / Shift+C joint / Cartesian control, Shift+1–4 the mode, Shift+F / P / E the options. Keys typed in a text field never drive the arm. Keyboard Control needs control of the Studio, lets go of every key after an E-STOP, when the window loses the focus, and when the Studio has not heard from the page for 0.3 s. In a browser tab, Ctrl+W still closes the tab.
