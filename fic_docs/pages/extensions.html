Writing Extensions

FIC Studio's optional pages — Sequences, Teach Mode, Script Editor, Experiments, Auto-Tuning, Teleoperation, Trackers, Battery Sorter, Trajectory Tests, VR ZED Teleop and more — are extensions you can toggle individually in Settings → Extensions. This page tells you how to write your own: with a web page (the way to build a new one, which works in the Studio window, on phones and on a headless board) or with a Qt page (how the existing ones are built; the web interface shows those automatically).

Quick start
python3 fic_install/new_extension.py my_tool "My Tool"

This copies the template (Extensions/_template/) to Extensions/my_tool/ with the id, name and class renamed. Enable it in Settings → Extensions, restart the Studio, and My Tool is in the page list with live robot readouts, a setting, a switch, buttons and a log. Edit extension.py and web/page.js from there; the walkthrough is below.

Why extensions

The Studio has a small core that every user needs — Dashboard, Multi-Robot, Tuning Panel, Robot Config, Topic Monitor, Safety, Settings — and a much larger surface of optional features that not every user does. Everything else, including former built-ins like Sequences, Teach Mode, Script Editor and Experiments, is an extension. Extensions let each user enable just the pages they care about, and let third parties add new pages without touching the core.

An extension is a folder under FIC_Interface/Extensions/<name>/ containing two files. The Studio locates the Extensions/ root relative to its own checkout automatically; set the FIC_ROOT environment variable to point it somewhere else.

  • manifest.json — metadata read at startup so the Studio can list the extension in Settings → Extensions without importing it.
  • extension.py — the Python module that gets imported only when the user enables the extension. Exports class Extension.
Discover-then-load

The Studio scans every Extensions/<name>/manifest.json on startup, but only imports the extensions whose IDs are in settings.extensions.enabled. A buggy disabled extension cannot break the Studio.

Two kinds of extension page

Since v5.1.0 the Studio's interface is a web page (shown in its own window, and to phones and other computers through the web remote). An extension's page can reach it in two ways:

Folder layout

FIC_Interface/
└── Extensions/
    ├── _shared/                    # private helpers shared between extensions
    │   ├── __init__.py
    │   ├── process_runner.py
    │   └── theme_helpers.py
    ├── battery_sorter/             # an example built-in extension
    │   ├── __init__.py             # empty
    │   ├── manifest.json
    │   ├── extension.py
    │   └── ...other scripts...
    ├── _template/                  # the template new_extension.py copies (not loaded)
    └── my_extension/               # YOUR extension goes here
        ├── __init__.py             # empty file
        ├── manifest.json
        ├── extension.py
        └── web/                    # its web page (optional)
            ├── page.js
            └── page.css            # optional

Folders whose name starts with _ (_template, _shared) are never loaded as extensions. The empty __init__.py turns the folder into a Python package so from my_extension.extension import Extension works. Folders without a manifest.json are skipped by discovery — they're treated as runtime helpers (e.g. the launchable scripts in Extensions/realsense_hand/ and Extensions/lemniscate/, and _shared/ itself). Discovery iterates folders in sorted (alphabetical) order, which is also the order they appear in Settings → Extensions. A manifest that fails to parse is skipped with a [extensions] Skipping <name>: ... message on the launching terminal's stdout — the rest of the Studio starts normally.

The Extension class contract

Your extension.py must export a class named Extension that subclasses fic_studio.extensions.Extension:

from PyQt5.QtWidgets import QWidget, QVBoxLayout
from fic_studio.extensions import Extension as ExtensionBase


class Extension(ExtensionBase):
    ID = "my_extension"
    NAME = "My Extension"
    DESCRIPTION = "Short sentence shown in Settings → Extensions."
    SIDEBAR_ICON = ""
    SIDEBAR_SECTION = "Experiments"

    def __init__(self, host):
        super().__init__(host)
        # Initialise local state ONLY. Extensions are constructed BEFORE the
        # toolbar and central widget are built, so host.robot_dropdown and the
        # main stack do not exist yet. host.node (the rclpy node) is available.
        self._page = None

    def build_page(self) -> QWidget:
        # Called once during MainWindow setup. Return the QWidget that will be
        # mounted as the extension's page.
        page = QWidget()
        layout = QVBoxLayout(page)
        layout.addWidget(self.host.make_page_title("My Extension"))
        # ... build the rest of the UI ...
        self._page = page
        return page

    def teardown(self) -> None:
        # Called when the user disables the extension (next launch) and on
        # app close. Stop any timers, kill any subprocesses, destroy any
        # publishers/subscribers you created.
        pass

    # OPTIONAL hooks
    def on_activate(self) -> None:
        # Called when the user clicks this extension's sidebar button.
        pass

    def on_emergency_stop(self) -> None:
        # Called when the user presses Space (or safety violation triggers).
        # Halt anything dangerous immediately.
        pass

on_emergency_stop(self)noHalt anything risky.

The web page

web/page.js is an ES module. Its default export draws the page once and returns how to refresh and leave it:

export default function build(root, api) {
  const { ui } = api;
  const speed = ui.slider({ label: 'Speed', min: 0, max: 1, step: 0.01,
    onChange: v => api.call('set_speed', { value: v }) });
  const go = ui.button({ label: 'Start', kind: 'solid', onClick: () => api.call('start') });
  root.append(ui.section('Motion', speed, ui.buttons(go)));
  return {
    update(state, studio) { speed.set(state.speed); go.set({ disabled: state.running }); },
    dispose() {},
  };
}
  1. The web UI imports the module when the page is opened and calls build(root, api).
  2. Every poll_ms it fetches web_state() and calls update(state, studio); studio is the Studio's own snapshot (robot, joints, pose, mode, …).
  3. api.call(name, args) runs web_action(name, args) in the Studio and resolves to its result, or to null when it was refused (the reason is already shown to the user). The page refreshes right after.
  4. dispose() runs when the user leaves the page.
api.What it is
idThe extension's id.
uiThe UI kit (below).
call(name, args)Run a web_action; a Promise of its result or null.
state() / studio()The last web_state() / the Studio's snapshot, outside update.
confirm(host, { title, lines, label, danger, onConfirm })Ask before something that matters, in place under host (the Studio never uses pop-up dialogs).
toast(text, isError)A short message at the bottom of the window.
h(tag, attrs, ...children)Make an element, for anything the kit does not cover.
Keep the page thin

All the logic lives in Python, where the robot, ROS and the settings are. The page only draws web_state() and turns clicks into api.call(). That way the same rules apply whoever is driving, and a page can never get ahead of the Studio.

api.ui builds the pieces the Studio's own pages are made of, so an extension looks native with no CSS of its own. Interactive pieces carry .set(value) so update() can refresh them without rebuilding; .set never overwrites a field the user is typing in.

Who may do what

  • Reading (web_state, the page files) needs the same sign-in and Extensions page permission as the rest of the web UI. View-only accounts can watch.
  • Acting (web_action) needs the control lease, like every command: one viewer at a time drives the robot. Remote users take it with Request control.
  • Actions listed in web.local_only run only from the Studio's own window, never from a phone or another computer.
  • E-STOP needs nothing and calls every extension's on_emergency_stop(). Stop what your extension drives there.
  • The Studio serves only scripts, styles and images (.js .mjs .css .json .svg .png .woff2) from web/, never HTML, and never anything outside web/.
  • on_activate() runs once before the first web_state or web_action, as when a classic page is opened, so timers an extension starts there also run for a web page.

How a Qt page looks in the web UI

An extension without a web page is mirrored: the Studio describes its widget tree (web_remote/qtmirror.py) and the web UI draws it with the kit. Group boxes become section cards; a bold or large label starts a new card with that label as its title; a label beside a field becomes the field's name; sliders become slider cards; consecutive buttons sit in a row; lists and tables become lists and tables; outer frames and scroll areas are left out. To make a Qt page mirror well:

  • Put each part of the page in a QGroupBox with a title, or start it with a bold label.
  • Put a QLabel just before each field, or give the field an objectName like max_speed (shown as "Max speed").
  • Give icon-only buttons a tooltip, an accessible name or an objectName.
  • Never open a QMessageBox or QInputDialog from a button: nobody can click it from a browser or on a headless board. Show the message in a label instead.

The host API

The host object passed to __init__ is an ExtensionHost — one instance per loaded extension, defined in fic_ws/src/fic_studio/fic_studio/extensions/host.py. It is the only way an extension talks to the Studio. Treat self.host as the entire Studio — never reach into main_window directly except when the API explicitly hands you a handle.

Pattern: publish to the target robot

rid  = self.host.target_robot_id
pubs = self.host.node.pubs.get(rid, {})
if pubs.get('mode_select'):
    pubs['mode_select'].publish(StringMsg(data="Joint Impedance"))

Equivalent shorthand for the common modes:

self.host.set_control_mode("Joint Impedance")  # publishes to host.target_robot_id

Pattern: react when the operator changes target

Connect the signal in __init__ or build_page (there is no separate setup hook):

def __init__(self, host):
    super().__init__(host)
    self.host.target_robot_changed.connect(self._on_target_changed)

def _on_target_changed(self, new_rid: str):
    self._teardown_subscribers()
    self._build_subscribers_for(new_rid)

Pattern: broadcast to every active robot (e-stop, pause-all)

def panic_stop(self):
    self.host.broadcast_stop()              # "Stop Controller" to every robot

def custom_broadcast(self):
    def push(rid):
        self.host.node.pubs[rid]['mode_select'].publish(StringMsg(data="Mode 1"))
    self.host.broadcast(push)

Migration tip

If you're moving an existing v3.2 extension forward: drop in the combo, then sweep self.host.node.station_robot_id → self.host.target_robot_id and self.host.node.<legacy_pub>.publish(…) → self.host.node.pubs[self.host.target_robot_id]['<key>'].publish(…). The legacy attributes still resolve to the first active robot, so you can do this incrementally.

Dialogs

If you need the entire Studio window as parent (e.g. for a file dialog before the page is shown), use host.main_window — but treat that handle as opaque. Don't poke at MainWindow internals through it.

Sidebar grouping

Each extension declares its SIDEBAR_SECTION. The Studio merges by section name:

  • If the section already exists as a built-in ("Tuning", "Programming", "Teleoperation", "Experiments", "System"), your button is inserted inside that existing section, alongside the built-in entries.
  • If the section is brand-new (e.g. "Vision"), a new section block is added between Experiments and System.
  • If a section ends up with no buttons (e.g. Teleoperation when both teleop and tracker extensions are disabled), its header is hidden automatically.

System is always last regardless of how many extensions are loaded.

From the template, step by step

  1. Make your copy: python3 fic_install/new_extension.py my_tool "My Tool" --section Programming. It refuses an id that exists already.
  2. Enable it: Settings → Extensions, tick My Tool, apply, restart the Studio. It is in the page list, in its section.
  3. Read the three files:
    • manifest.json: id, name, section and the web block, with reset_settings marked local_only.
    • extension.py: web_state() returns the robot's name, end-effector position and joint angles (from the host API), a gain, an on/off flag and a log; web_action() handles set_gain (checked and saved with host.set_setting), set_enabled, hello, publish (a std_msgs/String on /my_tool/message), clear_log and reset_settings. on_emergency_stop() switches it off.
    • web/page.js: four section cards (Robot, Settings, Actions, Log) built with the kit, refreshed in update().
  4. Change it: add a key to web_state(), show it in update(); add an action to web_action(), call it from a button. Restart the Studio after Python changes; reload the page (Ctrl+R in the window, or leave and come back) after page.js changes.
  5. Check it from a phone: open the web remote, sign in, take control, and use the page; reset_settings is refused there.

Moving a Qt extension to a web page

Extensions/sequences/ has both pages; compare its web_state/web_action and web/page.js with its build_page.

  1. Add the web block to manifest.json.
  2. Write web_state() from the state your Qt handlers already keep (Sequences: the sequence list, waypoints, playing index, status, loop and target).
  3. Write web_action() by calling the same handlers the Qt buttons call, so there is one state machine and the Qt page stays in sync. Replace every dialog with a check that raises ValueError (Sequences: deleting the last sequence, playing an empty one).
  4. Write web/page.js with the kit. Draw lists that change only when their content changed, so a field being typed in is not rebuilt.
  5. Keep build_page() while people still use --classic; remove it when they don't.

Hello World with a Qt page

The classic way, still supported: a tiny extension that publishes a heartbeat string at 1 Hz when the user clicks Start. The web UI shows this page through the mirror.

1. Create the folder

mkdir -p ~/FIC_Interface/Extensions/heartbeat
cd ~/FIC_Interface/Extensions/heartbeat
touch __init__.py

2. Write manifest.json

{
  "id": "heartbeat",
  "name": "Heartbeat",
  "description": "Publishes a 1 Hz heartbeat string to /heartbeat.",
  "sidebar_icon": "",
  "sidebar_section": "Experiments"
}

3. Write extension.py

import time

from PyQt5.QtCore import QTimer
from PyQt5.QtWidgets import QHBoxLayout, QLabel, QVBoxLayout, QWidget
from std_msgs.msg import String

from fic_studio.extensions import Extension as ExtensionBase


class Extension(ExtensionBase):
    ID = "heartbeat"
    NAME = "Heartbeat"
    DESCRIPTION = "Publishes a 1 Hz heartbeat string to /heartbeat."
    SIDEBAR_ICON = ""
    SIDEBAR_SECTION = "Experiments"

    def __init__(self, host):
        super().__init__(host)
        self._pub = None
        self._timer = None
        self._count = 0
        self._page = None
        self._count_label = None
        self._toggle_btn = None

    def build_page(self) -> QWidget:
        page = QWidget()
        layout = QVBoxLayout(page)
        layout.setContentsMargins(22, 20, 22, 20)
        layout.setSpacing(12)

        layout.addWidget(self.host.make_page_title("Heartbeat"))

        row = QHBoxLayout()
        self._toggle_btn = self.host.make_button("Start", "BtnPrimary")
        self._toggle_btn.clicked.connect(self._toggle)
        row.addWidget(self._toggle_btn)

        self._count_label = QLabel("Sent: 0")
        row.addWidget(self._count_label)
        row.addStretch()
        layout.addLayout(row)
        layout.addStretch()

        self._page = page
        return page

    def teardown(self) -> None:
        self._stop()

    def on_emergency_stop(self) -> None:
        self._stop()

    # ── Internals ─────────────────────────────────────────────────────
    def _toggle(self):
        if self._timer is None:
            self._start()
        else:
            self._stop()

    def _start(self):
        self._pub = self.host.node.create_publisher(String, "/heartbeat", 10)
        self._timer = QTimer()
        self._timer.timeout.connect(self._tick)
        self._timer.start(1000)
        self._toggle_btn.setText("Stop")
        self.host.log("INFO", "Heartbeat started", "Heartbeat")

    def _stop(self):
        if self._timer is not None:
            self._timer.stop()
            self._timer = None
        if self._pub is not None:
            try:
                self.host.node.destroy_publisher(self._pub)
            except Exception:
                pass
            self._pub = None
        if self._toggle_btn is not None:
            self._toggle_btn.setText("Start")

    def _tick(self):
        if self._pub is None:
            return
        msg = String()
        msg.data = f"hb {self._count} at {time.time():.3f}"
        self._pub.publish(msg)
        self._count += 1
        self._count_label.setText(f"Sent: {self._count}")

4. Enable it

  1. Launch the Studio.
  2. Open Settings → Extensions. Heartbeat appears in the list.
  3. Tick its checkbox, click APPLY, accept the restart prompt.
  4. After restart, the Experiments sidebar section gains a new Heartbeat entry.
  5. Click it, hit Start, and verify with ros2 topic echo /heartbeat.
Iterating on extension code

You don't need to colcon build to test extension changes — they live outside the ROS workspace. Just edit the file, restart the Studio.

Lifecycle

  1. Discovery at startup: every Extensions/<name>/manifest.json is parsed.
  2. Load: only manifests whose id is in settings.extensions.enabled get their extension.py imported.
  3. Construction: Extension(host) runs once. Robot dropdown and main_stack widgets do exist by this point, but you should still defer touching them until build_page.
  4. UI mount: build_page() is called once. Its return value is added to the main stacked widget; a sidebar button is appended to the matching section.
  5. Activation: when the user clicks the sidebar button, the page is shown and on_activate() fires. In the web UI it fires once, before the first web_state, web_action or mirrored control.
  6. Web page: while it is open, web_state() every poll_ms; web_action() per click.
  7. E-stop: when the safety subsystem fires (Space key, joint-limit violation, etc.), on_emergency_stop() is called on every loaded extension. Handle it idempotently — it may fire multiple times.
  8. Teardown: on app shutdown OR when the user disables the extension and restarts, teardown() is called. Stop timers, kill child processes, destroy ROS publishers/subscribers.

Common patterns

Subprocess management

If your extension launches external Python scripts and wants Start/Stop button toggles with crash detection, use the shared ProcessRunner:

from _shared.process_runner import ProcessRunner

class Extension(ExtensionBase):
    def __init__(self, host):
        super().__init__(host)
        self._runner = ProcessRunner(
            log_func=host.log,
            log_category="MyExt",
            log_prefix="my",   # log files land at /tmp/my_<key>.log
        )

    def _toggle_my_script(self):
        if self._runner.is_running("scriptA"):
            self._runner.stop("scriptA"); return
        argv = ["python3", "-u", "/path/to/script.py", "--robot-id", self.host.node.station_robot_id]
        self._runner.start("scriptA", argv, self._scriptA_btn, "Script A")

    def teardown(self):
        self._runner.stop_all()

Each extension owns a separate ProcessRunner instance, so two extensions can both manage subprocesses without colliding. The runner handles button styling (red while running), 1 Hz watchdog polling, and logs the last 6 lines of stdout/stderr if the script exits non-zero.

ROS publishers and subscribers

from rclpy.qos import qos_profile_sensor_data
from std_msgs.msg import Float64MultiArray

def _start(self):
    self._pub = self.host.node.create_publisher(
        Float64MultiArray, "/my_topic", qos_profile_sensor_data)
    self._sub = self.host.node.create_subscription(
        Float64MultiArray, "/feedback", self._on_feedback, qos_profile_sensor_data)

def teardown(self):
    if self._pub:
        try: self.host.node.destroy_publisher(self._pub)
        except Exception: pass
    if self._sub:
        try: self.host.node.destroy_subscription(self._sub)
        except Exception: pass

Gotchas

  • The Extension class is not a QObject. If you need to parent a QObject (e.g. QTimer with a parent), pass host.main_window, not self.
  • build_page runs after toolbar setup but inside _setup_central_widget. host.robot_dropdown exists, but the rest of the sidebar/main_stack is still being built. Don't try to navigate (setCurrentIndex) from inside build_page.
  • Don't write to host.current_joint_positions — it's read-only. The shared attribute is populated by core mixins; your extension should read it, not stomp on it.
  • Dialogs block in the web UI. A QMessageBox or QInputDialog opened from a mirrored button waits for a click nobody can give from a browser, and a headless board has no screen at all. Show messages in a label (Qt page) or raise ValueError (web action).
  • web_state() runs often. Keep it to reading attributes; do slow work in timers or threads and store the result.
  • Mode publishing is free-for-all. host.set_control_mode(...) publishes immediately with no arbitration. If two enabled extensions try to claim the controller at once, last write wins. Coordinate via UI (e.g. disable one button while the other is active).
  • Don't import from fic_studio.mixins.* in your extension. Those are subject to change. Stick to the host API and fic_studio.extensions.

Distributing extensions

An extension is just a folder. To share one, zip Extensions/<name>/ and have the recipient extract it into their own FIC_Interface/Extensions/. No installation, no setup.py, no colcon. After they restart the Studio it appears in Settings → Extensions ready to enable.
