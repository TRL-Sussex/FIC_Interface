Logs

Timestamped Studio messages, on their own page.

Overview

The Logs page shows timestamped messages from all GUI components — process events, commands sent, errors, safety warnings, and more. It carries a header bar (LOGS title, level filter, Clear and Save buttons) above the scrolling text area.

Reach it from the Logs entry in the sidebar, pinned directly above Help, or with Ctrl+L.

Moved in v4.2.0

Logs used to be a fixed-height strip pinned under every page. It competed for vertical space with the page content and, once the control bar took the bottom edge, with the bar as well. On its own page it gets the full area and needs no collapse affordance, so the ☰ button and the height setting are gone. Ctrl+L now navigates here rather than toggling a strip.

GUI messages only

The Log Viewer shows messages generated by the Studio itself, not the stdout of the ROS 2 nodes it launches. Simulator output is redirected to /tmp/fic_sim_<package>_<timestamp>.log, and the FIC controller runs with its output discarded. To watch node output live, run the processes from a terminal instead — see Processes and Dev Console.

Log Levels

Colours come from the active Warmth theme tokens, so they adapt to warmth_dark / warmth_light.

Log Entry Format

[HH:MM:SS] LEVEL [Source] Message text

Example entries (as produced by the current code):

[14:32:01] INFO  [Process] MuJoCo simulation started for Franka_FR3 (log: /tmp/fic_sim_..._....log)
[14:32:03] INFO  [Process] FIC controller started for Franka_FR3 (7 joints)
[14:32:05] INFO  [Control] Joints: [0.0°, 30.0°, -60.0°, 0.0°, 90.0°, 0.0°, 0.0°]
[14:32:15] WARN  [Safety] Safety limit exceeded: Z max = 1.512 (limit: 1.500)
[14:32:20] ERROR [Safety] E-STOP ACTIVATED! HALTING ALL SYSTEMS AND PROCESSES.

Saved files use the same fields but without brackets around the source.

Sources

The [Source] field indicates which component generated the message. Core sources:

SourceDescription
SystemApplication startup, robot configs loaded
ProcessStart/stop of SIM, FIC, API (driver), BAG, PLT processes; crash diagnostics
CleanupChild processes terminated on exit or E-STOP
ControlJoint/Cartesian/mode/home commands sent
robot1 … robot4Per-robot publishes (gripper, pose, STOP) in multi-robot setups
Robot / ConfigRobot selection and configuration changes
SafetyLimit warnings, zone violations, E-STOP
SettingsSettings saved/applied
BuildBuild Tools events
Gamepad / Teleop / VRInput-device and teleoperation events
Dashboard / Monitor / ViewDashboard quick actions, topic monitor, view-mode changes

Extensions log through the host API and default to their extension id as the source; several override it with a friendlier name: Teach, Tracker, Sequence, Script, Experiment, Tuning, VR ZED. See Extensions.

Simulation crash diagnostics

If the simulation subprocess dies during its warmup window (2 s for the CPU MuJoCo simulator, 8 s for Newton while CUDA kernels JIT-compile), the Log Viewer receives an ERROR entry with the full log path plus the last 12 non-empty lines of the log file, each prefixed   |. Check these lines first when the SIM button flips back to ▶ SIM on its own.

Two settings keys are now inert

general.show_log_viewer and general.log_viewer_height sized and toggled the old bottom strip. With Logs on its own page there is nothing to size or hide, so both are ignored. They are still read and written so older settings files load unchanged.

Settings persist in ~/.robot_selector_gui_settings.yaml.

For Extension Developers

Inside an extension, log through the host API rather than printing to stdout:

self.host.log("INFO", "Trial 3/10 complete", "Experiment")
self.host.log("WARN", "Waypoint timeout")   # source defaults to the extension id

The message lands in the Log Viewer with the same formatting and level colours as core messages. See the API Reference for the full host API.
