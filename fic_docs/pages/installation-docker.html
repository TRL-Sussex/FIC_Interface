Installation (Docker)

Run the whole FIC Control Studio on Windows, macOS or Linux with only Docker installed. The Studio's desktop opens in your web browser.

What you get

The Studio and the Dev Console, the MuJoCo simulator, the FIC controller and the extensions that work in simulation, already built, in one image (ghcr.io/trl-sussex/fic_interface). It is simulation only: nothing in it talks to a real robot. For hardware, use the Linux install. The full reference is docker/README.md in the repository.

How it works

  1. A container starts from the image, downloaded the first time (about 1 GB).
  2. Inside it, a virtual desktop starts and FIC Control Studio opens on it.
  3. The desktop is shown in your browser at http://localhost:6080. MuJoCo windows, the plotter and these docs open there too.
  4. Nothing is lost when you stop it. Settings, tuning and robots you add are kept in the Docker volume fic-studio-home. Recordings and your own extensions go to the folder FIC_Studio in your home folder.
  5. It is password-protected. Every start gets a new random password, built into the link the launcher opens.

The launcher (docker/fic-studio.sh on macOS/Linux, docker/fic-studio.cmd on Windows) does all of this. Give Docker 4 or more CPUs and 8 GB of memory (Docker Desktop → Settings → Resources); the 3D view is drawn on the CPU, so more cores make it smoother.

Windows 10 / 11

  1. Install Docker Desktop for Windows. Keep Use WSL 2 ticked, and restart if asked. If it reports that WSL 2 is missing, run wsl --install in PowerShell as Administrator and restart.
  2. Start Docker Desktop and wait for Engine running. No Docker account is needed.
  3. On a shared lab PC, your account must be in the docker-users group (an administrator runs net localgroup docker-users <your user> /add; then sign out and back in).
  4. Get the repository (clone it, or download it as a ZIP and unzip it).
  5. Double-click docker\fic-studio.cmd. It downloads FIC Studio the first time, waits for it and opens your browser. If SmartScreen appears, click More info → Run anyway.

Your shared folder is C:\Users\<you>\FIC_Studio.

macOS (Apple Silicon or Intel)

  1. Install Docker Desktop for Mac for your chip, start it, and wait for Engine running. The image runs natively on Apple Silicon; Rosetta is not needed.
  2. Clone the repository (outside Desktop, Documents and Downloads).
  3. In Terminal: 
    cd <the repository>/docker
./fic-studio.sh
    If it says permission denied, run chmod +x fic-studio.sh once.

Linux (Ubuntu)

  1. Install Docker (once), then log out and back in: 
    curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
  2. Start FIC Studio: 
    cd <the repository>/docker
./fic-studio.sh

On Linux, ./fic-studio.sh --native opens the Studio and MuJoCo windows directly on your desktop instead of in the browser.

Check that it works

  1. The browser shows FIC Control Studio, with KinovaGen3_7DOF selected and Target Simulation.
  2. Press ▶ Start. A MuJoCo window opens with the arm.
  3. The Dashboard shows simulator and fic controller running, with live joint values.

For a full check (about two minutes): docker exec fic-studio fic-selftest. Then continue with the Quick Start Guide.

Limits

  • Simulation only: no robot drivers.
  • No Newton (GPU) backend: it needs an NVIDIA GPU with CUDA. The CPU MuJoCo simulator is included.
  • Gamepads work only on Linux hosts (add --device /dev/input/js0 to docker run).

If the image is not public

Until the package is public, docker pull ghcr.io/trl-sussex/fic_interface:latest says unauthorized or denied. Use one of these instead.

A. Download it while it is private

  1. On GitHub: your picture → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic). Tick only read:packages and copy the token.
  2. docker login ghcr.io -u <your GitHub username>, and paste the token as the password.
  3. Start as usual: ./fic-studio.sh (Windows: fic-studio.cmd). That is ghcr.io/trl-sussex/fic_interface:latest, built from the main branch. To pin a release, name it: ./fic-studio.sh --image ghcr.io/trl-sussex/fic_interface:v5.6.0 (Windows: fic-studio.cmd -Image ghcr.io/trl-sussex/fic_interface:v5.6.0).

B. Load a file someone gave you

docker load -i fic-studio_local.tar.gz
./fic-studio.sh --image fic-studio:local

C. Build it yourself

Only if A and B do not work. Follow the steps below.

Building the image yourself, step by step

This builds fic-studio:local from the source code and runs it. You need Docker, Git, about 10 GB of free disk space and 15 to 30 minutes. Type each line, one at a time, and wait for it to finish.

On Windows 10 / 11 (PowerShell)

  1. Install Docker Desktop (as above) and Git for Windows with its default options (it includes Git Bash).
  2. Docker Desktop → Settings → Resources: at least 4 CPUs and 8 GB. Apply & restart.
  3. Open PowerShell and check Docker: 
    docker version
    If it says docker is not recognized, Docker Desktop was installed for your user only. Fix it for this window: 
    $env:Path = "$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin;$env:ProgramFiles\Docker\Docker\resources\bin;$env:Path"
  4. Go to where you want the code: 
    cd $HOME
  5. Download the code with Linux line endings (scripts with Windows line endings fail inside the image with python3\r: No such file or directory): 
    git clone -c core.autocrlf=false -c core.longpaths=true --branch main https://github.com/TRL-Sussex/FIC_Interface.git FIC_Docker_Build
    main is the branch the image is built from. A warning about Pendulum.urdf colliding is harmless. Do not build from a clone made with default Git settings.
  6. Go into it: 
    cd FIC_Docker_Build
  7. Build the image and run the self-test: 
    & "$env:ProgramFiles\Git\bin\bash.exe" docker/build.sh --test
    or, without Git Bash and without the self-test: 
    docker buildx build --file docker/Dockerfile --tag fic-studio:local --load .
  8. Check that the image is there: 
    docker image ls fic-studio
  9. Start it: 
    .\docker\fic-studio.cmd -Image fic-studio:local
  10. Optional: make it the default (then open a new PowerShell window): 
    setx FIC_IMAGE fic-studio:local
  11. After changing or pulling code: 
    git pull
& "$env:ProgramFiles\Git\bin\bash.exe" docker/build.sh
.\docker\fic-studio.cmd restart -Image fic-studio:local

On macOS or Linux

  1. Install Docker (as above) and give it 4+ CPUs and 8+ GB.
  2. Check Docker: 
    docker version
  3. Download the code: 
    cd ~
git clone --branch main https://github.com/TRL-Sussex/FIC_Interface.git FIC_Docker_Build
cd FIC_Docker_Build
  4. Build the image and run the self-test: 
    ./docker/build.sh --test
  5. Check that the image is there: 
    docker image ls fic-studio
  6. Start it: 
    ./docker/fic-studio.sh --image fic-studio:local
  7. After changing or pulling code: 
    git pull
./docker/build.sh
./docker/fic-studio.sh restart --image fic-studio:local
Handing the image to someone else

docker/build.sh --save writes docker/dist/fic-studio_local.tar.gz. They load it with docker load -i fic-studio_local.tar.gz and start it with --image fic-studio:local. An image built on an Intel/AMD PC runs on Intel/AMD computers; one built on Apple Silicon runs on ARM computers.
