Quick Start Guide

This page gets you from a built workspace to a moving simulated robot in a few minutes, then covers the hardware paths. If you have not built the workspace yet, do Installation first.

Launching the Studio

Three equivalent ways to start the Full Studio:

MethodHow
Desktop entrySuper → search FIC Control Studio (installed by fic_install/install-desktop-entry.sh)
Launcher scriptbash <FIC_Interface>/fic_install/fic-control-studio.sh — auto-sources ROS 2, builds the workspace if needed, then launches
Directsource fic_ws/install/setup.bash && ros2 run fic_studio fic_studio_pro

The lightweight FIC Dev Console has matching entries: desktop search “FIC Dev Console”, fic-dev-console.sh, or ros2 run fic_studio fic_dev.

First-launch wizard

On the very first launch, a 4-step setup wizard opens: pick your primary robot, verify the workspace (checks src/, fic_library, config.xml, robots_config.yaml, install/, setup.bash), optionally run a test launch (MuJoCo + FIC controller + /trajectory_data check), and choose what to open first. To re-run it later, set general: wizard_completed: false in ~/.robot_selector_gui_settings.yaml.

Simulation (Full Studio)

  1. Launch FIC Control Studio
  2. Select a robot from the toolbar dropdown (e.g. Franka_FR3)
  3. In the toolbar Target selector, pick Simulation
  4. Click ▶ Start — the MuJoCo simulator launches, and the FIC controller auto-starts 2 seconds later. The SIM and FIC status-bar LEDs turn green.
  5. Open ▲ Joint on the control bar, pick a control mode from the menu — Mode 2 (Joint Impedance With Planner) is the safest first motion — and use the joint fields or Home button, then ▶ Send command (or tick Live publish)
  6. Open the Tuning Panel to adjust FIC parameters in real time
Sequencing is automatic

The single Start button handles ordering for you: simulator first, FIC controller 2 s later. Clicking Start again stops both. The Target selector and robot dropdowns lock while a session is running — stop first to switch.

The simulator output is logged to /tmp/fic_sim_<backend>_<timestamp>.log; if the simulator dies during startup, the studio surfaces the last log lines in an error dialog. The default backend is the CPU MuJoCo simulator (mujoco_native); an optional Newton GPU backend can be selected in Settings → Simulation (see Simulation). Newton’s first launch JIT-compiles CUDA kernels, so its startup health check waits 8 s instead of 2 s.

Hardware (Full Studio)

  1. Select your robot, set Target to Hardware, and click ▶ Start
  2. The vendor driver (Franka/Kinova API) starts first; the FIC hardware controller auto-starts 2 seconds later
  3. Use the control bar (Hardware target) for joint/Cartesian/gripper commands
  4. Safety limits from Robot Config are enforced automatically — see Safety

The driver command comes from Robot Configuration → Edit → File Paths → Driver Command (placeholders {robot_lib} and {robot_name} are expanded). If none is configured, Start shows a dialog pointing you there. Driver stdout is streamed into the log panel; if the driver exits on a fault you get a “Driver exited (code N)” warning and can click Start again.

Safety First

Start with low stiffness. Keep E-STOP (Space) accessible. Test in simulation first — work through the First Motion checklist before powering a real arm.

Hardware (Dev Console)

Use this on a PC next to the real robot for direct control or as a teleop follower. Unlike the Full Studio, the Dev Console keeps separate toolbar buttons for each process.

  1. Launch FIC Dev Console (Super → search “FIC Dev Console”)
  2. Select the robot from the toolbar dropdown
  3. Click ▶ API (or F9) to start the vendor driver
  4. Click ▶ FIC (or F8) to start the hardware controller
  5. Select a control mode from the toolbar Mode dropdown and click Send
  6. Use the Control tab to send joint/Cartesian/gripper commands
  7. For teleoperation, switch to the Teleoperation tab and click START TELEOP

FIC Dev Console has detailed instructions for both direct control and teleoperation workflows.
