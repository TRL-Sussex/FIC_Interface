Dashboard

Grouped numeric monitoring — the instrument panel, not the controls.

Overview

The Dashboard is the default landing page (stack index 0, Ctrl+0). As of v4.2.0 it is a dense, read-only numeric readout modelled on the KINOVA Kortex Web App's Monitoring page: data grouped into Base · Joints · End effector · Safety, split across Overview and Detailed tabs.

It carries no robot-driving controls. Commanding lives on the control bar docked beneath it, which is present on this page as on every other.

Nothing here is invented

Any channel with no live source renders --. The Dashboard never falls back to a last-known value presented as live, and never shows a fabricated zero.

Overview tab

BASE

Kinova's Base group answers “what state is the system in”. Here that is which processes are up — and the rows keep their ▶/■ controls, so nothing you could do from the old session card is lost.

JOINTS

One row per joint, in degrees:

ColumnSource
commandedjoint_commanded_for(rid)
positionjoint_positions_for(rid) ← {rid}_q_current
errorcommanded − position
velocityjoint_velocity_for(rid)
torquejoint_effort_for(rid)

Rows are addressed by name, not index, so a robot reporting more than its actuated joints — the CSPM's passive and platform joints — tables correctly rather than being truncated to the first seven.

END EFFECTOR

Rows commanded / pose / error / velocity across x y z and the θx θy θz triple. The Euler convention is x-y-z extrinsic, matching what the Kinova Web App reports; the conversion clamps before asin so a pitch at ±90° cannot raise a domain error.

Beneath it, the tool wrench: force and torque per axis, |F| and |τ| magnitudes, and a contact indicator that trips above 5 N.

Commanded pose reads --

No publisher carries a commanded end-effector pose yet, so that row stays blank rather than echoing the actual pose back as though it were a target. The row exists so it populates the day a source appears.

SAFETY

Joint limits, velocity limits and force/torque indicators. Joint proximity warns within 5% of the configured range; torque within 10% of the limit. Velocity has no limit source yet and always reads OK.

Detailed tab

Kinova's Detailed view adds motor currents, voltages and temperatures. FIC publishes none of those, so rather than print a group of dashes this tab shows what this stack genuinely knows:

CardContent
JOINTS · limits and headroomThe Overview columns plus τ max, % τ, limit lo, limit hi and % range — how much headroom each joint has against its configured ceilings.
END EFFECTORPose, commanded, error and velocity at four decimals, plus a quaternion row alongside the Euler triple.
TOOL WRENCHForce and torque per axis with magnitudes.
ROBOTModel, joint count, gripper and range, EE frame, elbow frame, torque sign, gravity compensation, wrench source and URDF path — all from robots_config.yaml.
TELEMETRY CHANNELSWhich channels carry data, plus the admittance deadbands (τ 2.0 · F 4.0 · M 0.2).
Presence, not a fabricated age

Only joint state is timestamped in JointStateMixin. That row reports a real sample count and age; the others report streaming or no data rather than an age nothing measures.

Refresh

A 20 Hz timer drives the page, and only the visible tab refreshes. Off the Dashboard the refresh returns on a single integer comparison, so the cost of the timer while you are elsewhere is negligible.

What changed in v4.2.0

The previous Dashboard was a three-zone hub of graphical widgets — commanded-vs-actual dual-track bars, effort bars, a trajectory sparkline and wrench bars. Those are replaced by the grouped numeric tables above. DualTrack was removed as unused; LimitBar and TrajectoryPlot remain and are still used by the Topic Monitor.
