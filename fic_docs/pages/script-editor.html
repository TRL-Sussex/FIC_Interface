Script Editor

Python scripting with the robot.* control API for automated sequences, live telemetry, and full programmatic access to everything the GUI can do.

Overview

The redesigned Script Editor (v3.9.2, "Complete Script Control API") is a three-zone layout that gives you a complete programmatic control layer over the robot. Scripts run in a background thread (ScriptRunner, a QThread) so the GUI remains responsive. A cooperative stop mechanism replaces the old hard-kill, so in-flight moves unwind cleanly. Joint angles are in degrees throughout the API; the only radians you will see are the rx/ry/rz Euler arguments of move_cartesian and the values returned by the legacy trajectory helpers.

The extension lives in Extensions/script_editor/ (extension.py for the UI and runner, robot_api.py for the RobotAPI facade) and appears in the Programming sidebar section when enabled in Settings → Extensions.

In the web interface (and the Docker image) the Script Editor has its own page: a full-width editor, the output under it, and Examples and API drawers. The Classic interface keeps the layout under The Classic page.

Target Routing

On the web page a run goes to the Studio's own target (the top bar; shown as Runs on), and Run asks first when it is Hardware. The Classic page's Target dropdown chooses for the Classic page's runs. The Target dropdown determines where commands are sent. move_joints automatically picks the right publisher based on the active target (VR routes like Simulation):

TargetPublisher used by move_jointsJoint feedback topic
Simulationpublish_joint_angles/robot{N}_simulation/joint_states
Hardwarepublish_real_joint_angles/joint_states
VRpublish_joint_angles/robot{N}_simulation/joint_states

Blocking waits (wait=True) do not subscribe to these topics themselves — they read the Studio's built-in joint-state cache (JointStateMixin) for the target robot. Switch target from a script with robot.target.set_target('simulation'|'hardware'|'vr') (marshalled to the GUI thread, so the dropdown follows); read it back with robot.target.current or robot.target_mode. See Topics for the full multi-robot topic map.

Hardware target

With Target = Hardware, move_joints publishes directly to the real-robot command path. The web page asks before running on Hardware; the Classic page does not. Test every script against Simulation first, and keep the E-STOP reachable — it also signals a running script to stop.

Who can run scripts

Any browser that holds control in the web interface can save and run scripts, and a script is ordinary Python with the Studio's rights — it can also switch the target itself. Keep sign-in on whenever the web interface is open to a network (Web Remote › Signing in). The Docker image serves it to this computer only; started with --lan, it serves your network with sign-in on.

The robot API — Grouped Namespaces

Every script receives a robot object with eight grouped sub-APIs (state, motion, mode, process, target, tune, safety, topics), plus the top-level helpers robot.wait(seconds), robot.is_stopped(), robot.rid, and robot.target_mode. Joint angles are in degrees, distances in metres.

robot.state — Live Telemetry (read-only)

PropertyReturnsDescription
robot.state.jointslist[float] (deg)Current joint positions
robot.state.joint_velocitylist[float] (rad/s)Per-joint velocities
robot.state.joint_effortlist[float] (Nm)Per-joint torque/effort
robot.state.joint_commandedlist[float] (deg)Last commanded joint angles
robot.state.ee_poselist [x, y, z, qx, qy, qz, qw]End-effector pose (metres + quaternion); empty list [] when unknown
robot.state.wrenchtuple (Fx, Fy, Fz, Tx, Ty, Tz)Tool wrench in N / Nm; None when unavailable

State reads are thread-safe direct calls into the Studio's joint-state cache — no marshalling, so they are cheap to poll in a loop. There is no robot.state.mode or .target; use robot.target_mode for the target, and the legacy trajectory helpers (below) for controller internals.

robot.target — Switch Active Target

robot.target.set_target('simulation')   # switch to sim (updates the GUI dropdown too)
robot.target.set_target('hardware')     # switch to hardware
robot.target.set_target('vr')           # switch to VR

print(robot.target.current)             # 'simulation' | 'hardware' | 'vr'
print(robot.target_mode)                # same, as a top-level property

robot.target is an object, not a function — calling robot.target('simulation') raises TypeError.

robot.tune — Tuning Parameters

MethodDescription
robot.tune.param_update(param_type, value)Publish a parameter-update string via node.publish_param_update (thread-safe direct publish).
robot.tune.save(robot_name=None, joint_id=1, mode=1, params=None)Save a parameter dict to the tuning XML via XMLManager.save_joint_params (marshalled). See Config XML.

Profile selection lives on robot.mode.active_profile(name), not on robot.tune.

robot.safety — Emergency Stop

MethodDescription
robot.safety.estop()Publish mode 1 directly (parks the robot), then trigger the GUI broadcast_stop handler on the main thread for process cleanup.
robot.safety.broadcast_stop()Send stop to every active robot (marshalled).

robot.topics — Raw Topic Access

MethodDescription
robot.topics.list_topics()Return (topic_name, type_string) tuples from the ROS graph.
robot.topics.subscribe(name)Subscribe by name; the message type is auto-discovered from the graph. Common std_msgs/sensor_msgs/geometry_msgs types are built in; other types are imported dynamically from the type string.

robot.topics.unsubscribe(name)Destroy the subscription and clear the cached value.

There is no generic publish() — publishing goes through the typed robot.motion / robot.mode / robot.tune methods. All script subscriptions are cleaned up automatically when the script finishes or is stopped. Use the Topic Monitor to explore what is on the graph.

Legacy Trajectory Helpers

Scripts also receive read-only helpers that lazily subscribe to the controller's {rid}_trajectory_data stream and return controller-internal signals in radians / Nm: get_trajectory() (full parsed dict), get_current_joints(), get_target_joints(), get_joint_errors(), get_control_effort(), get_planner_targets(), get_admittance_targets(), get_desired_effort(), get_measured_effort(), get_ee_desired(), get_ee_error(), get_ee_admittance_target(), get_rotation_error(), get_torque_commands(), and get_gripper_width(). These only return live data while a FIC controller is running. set_velocity() is deprecated and only logs a message.

Blocking Move-and-Wait

Pass wait=True to move_joints to block until the robot reaches the target:

# Block until joints reach target (within the 2.0 deg default tolerance)
reached = move_joints([0, -45, 0, -90, 0, 45, 0], wait=True, timeout=10.0)

# Tighter tolerance
reached = move_joints([0, -30, 0, -60, 0, 60, 0], wait=True, tolerance=0.5, timeout=15.0)
print('reached' if reached else 'timeout or stopped')

The wait polls robot.state.joints at ~20 Hz. It returns True when every joint is within tolerance degrees, False on timeout or cooperative stop.

move_cartesian has no wait= option. To block on a Cartesian target, poll the EE pose yourself:

move_cartesian(0.4, 0.0, 0.5)
deadline = time.monotonic() + 15.0
while time.monotonic() < deadline and not is_stopped():
    ee = robot.state.ee_pose
    if ee and abs(ee[0]-0.4) < 0.005 and abs(ee[1]) < 0.005 and abs(ee[2]-0.5) < 0.005:
        print('EE target reached')
        break
    wait(0.05)

Cooperative Stop

Clicking Stop sets a per-run threading.Event. Calls that poll it — move_joints(wait=True), wait(), wait_until_stopped(), and your own is_stopped() checks — abort cleanly. The Studio then waits up to a 2-second grace period; if the thread is still alive, terminate() is used as a last resort and the console prints [FORCE TERMINATED — grace period expired] instead of [Stopped cooperatively]. Pressing the global E-STOP sets the same event and additionally fires robot.safety.estop(). When the extension is torn down, latched flags (admittance_planner, hapfic) are restored to safe defaults.

sleep() is not interruptible

sleep() is plain time.sleep — it does not poll the stop flag. A loop built on sleep() (or a tight while True: pass) can only be killed by the hard terminate() fallback. Use wait() for delays and check is_stopped() in loop conditions so Stop works cooperatively.

Run / Stop Lifecycle

State reads and motion/mode publishes go straight to the ROS node from the worker thread (thread-safe); anything that touches Qt widgets or subprocesses (robot.process.*, robot.target.set_target, robot.tune.save) is queued to the GUI thread via marshal(). stdout is intercepted per-thread, so only the script's own print() calls land in the Output Console.

Example: E-Stop on Force Threshold

# Emergency stop if measured Fz exceeds a threshold
while not is_stopped():
    w = robot.state.wrench          # (Fx, Fy, Fz, Tx, Ty, Tz) or None
    if w and abs(w[2]) > 20.0:
        print("Force threshold exceeded - issuing E-stop")
        robot.safety.estop()
        break
    wait(0.05)

Install API Button

The toolbar's Install API button installs the standalone fic_api Python package in editable mode from <FIC_Interface>/fic_api/ (resolved via FIC_API_DIR in fic_studio/config.py), running the command in a build dialog so you can watch the pip output. Once installed, you can drive the robot from any Python environment — terminals, Jupyter notebooks, IDEs, or CI pipelines — without the GUI:

# What the Install API button runs:
python3 -m pip install --break-system-packages -e ~/FIC_Interface/fic_api
Standalone Python API

The standalone package exposes a flat Robot class (its surface differs from the in-editor robot.* namespaces — e.g. home() takes no arguments and there is no wait=True):

from fic_api import Robot

with Robot(target='simulation') as r:
    r.home()
    print(r.get_joint_positions())   # degrees

See Script API / Python API for the full standalone reference, including constructor parameters, generic topic subscription, and advanced examples.

Execution

  • Scripts run in a separate thread (ScriptRunner, a QThread) so the GUI stays responsive; each run gets a fresh namespace and stop event.
  • All Robot API functions and flat aliases are injected into the script's namespace automatically.
  • Use print() to send output to the console — stdout is routed per-thread, so background threads you spawn will print to the terminal, not the console.
  • Exceptions are caught and displayed with full tracebacks; the run ends with a === Script completed/failed === line.
  • Click Stop to cooperatively terminate a running script (2-second grace, then hard kill). Any topic subscriptions the script created are cleaned up on finish or stop.
  • Full builtins are available — sandboxing is intentionally omitted for research use.

For fixed waypoint playback without writing code, see Sequences and Teach Mode. See Script API / Python API for the complete method list with signatures — Part 1 covers Script Editor injection functions, Part 2 covers the standalone fic_api package.
