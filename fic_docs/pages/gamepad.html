Gamepad Control

Xbox-compatible gamepad teleoperation following the Kinova paradigm — works in all 8 FIC control modes.

Overview

FIC Studio reads Xbox/compatible USB gamepads directly via the Linux joystick protocol (/dev/input/jsN) — no ROS joy node or external driver is needed. Plug in a controller, and the status bar shows a green GAMEPAD LED; once you start pressing buttons the label is replaced by the current control state. Devices are hot-plug scanned at 2 Hz, so controllers can be connected and removed mid-session.

The control scheme follows Kinova’s standard gamepad interface:

  • Back toggles between Joint and Cartesian control space
  • Start cycles FIC sub-modes (Impedance → Planner → Admittance → Admittance Haptic)
  • LB / RB selects which joint is active (joint mode only)
  • Triggers provide proportional gripper control
  • Face, shoulder and stick-click buttons are user-remappable in Settings; the triggers and D-pad are fixed

Control Spaces

Joint Mode

Follows the Kinova single-joint-plus-neighbour approach. The left stick Y drives the currently selected joint, and the right stick Y drives the next joint (selected + 1). Press LB / RB to shift the selection one joint at a time (selection wraps around past the last joint).

SelectionLeft Stick YRight Stick Y
J1, J2 (default)Joint 1Joint 2
J2, J3Joint 2Joint 3
J3, J4Joint 3Joint 4
………
J7 (7-DOF arm)Joint 7— (skipped)

Stick deflection maps to joint velocity (deg/s), integrated at 100 Hz into position targets. Targets are clamped to the robot’s joint_limits_deg from fic_studio_robots.yaml (see Robot Configuration); a joint with no limits entry falls back to ±180°. Joint targets are seeded from live joint state feedback before the first command is sent.

Tip

Joint targets are seeded from the robot’s current position when you first move a stick or switch to joint mode. If no joint state has been received yet (controller not running), the gamepad logs a warning and waits.

Cartesian Mode

All four stick axes are active simultaneously — no group cycling needed:

StickRobot AxisMotion
Left Stick XY translationLeft / Right
Left Stick YZ translationUp / Down
Right Stick YX translationForward / Back
Right Stick XYaw rotationRotate

Roll and pitch are not mapped to the gamepad — use the GUI pose inputs for orientation adjustments beyond yaw.

Stick deflection scales by the current speed preset. Displacements are integrated into an absolute geometry_msgs/Pose published at 100 Hz while a stick is deflected. The target pose is seeded from the live end-effector pose (or the YAML default_ee_target if unavailable).

Tool-frame motion

Cartesian displacements are applied in the end-effector (tool) frame, not the world frame: translations are rotated by the current target orientation before being added, and yaw rotates about the tool’s Z axis. With the tool pointing down this feels world-aligned, but after rotating the end effector, “forward” follows the tool — not the robot base.

Sub-Modes

Press Start to cycle through the four FIC sub-modes within the current control space. The mode is shown in the status bar after the pipe character. See Control Modes for what each mode does.

#Joint Space#Cartesian Space
1Joint Impedance5Cartesian Impedance
2Joint Impedance With Planner6Cartesian Impedance with Planner
3Joint Admittance7Cartesian Admittance
4Joint HAP-FIC8Cartesian HAP-FIC

Switching sub-mode publishes both the control_mode integer and the mode_select string to reach both simulation and hardware nodes. The sub-mode slot is preserved when toggling control space with Back: if you are on Cartesian Impedance with Planner (slot 2) and switch to joint space, you land on Joint Impedance With Planner (also slot 2).

Speed Presets

D-pad Up / Down cycles through three speed levels. The current level is shown in the status bar. Cartesian steps are applied per 100 Hz tick at full stick deflection, giving the effective maximum speeds below.

Gripper

The triggers provide proportional velocity-based gripper control:

  • RT (right trigger) = open
  • LT (left trigger) = close

Trigger deflection controls the rate of gripper movement, not the position directly. Harder press = faster movement. Full trigger deflection opens or closes the gripper fully in approximately 2.5 seconds (rate 0.4/s of full stroke). Release the trigger and the gripper holds its position. Both triggers pressed together cancel out (net deflections below 5% are ignored).

The internal 0–100% value is converted to metres with a fixed 0.08 m scale (matching the Robotiq 2F-85 stroke and the GUI slider convention) before publishing on {rid}_gripper_width.

E-STOP behaviour

Pressing B (default) triggers the studio’s global E-STOP — the same path as the toolbar E-STOP button: extensions are halted, a graceful torque ramp-down (mode 0, “Stop Controller”) is broadcast to every active robot, and controller processes are then torn down as a backstop. See E-STOP and Safety for details.

Home Button

Pressing A (default) sends the robot to its q_home_deg configuration from fic_studio_robots.yaml. This:

  1. Switches the gamepad to joint space and Joint Impedance mode (Mode 1)
  2. Publishes the home joint angles (converted to radians) on {rid}_desired_joint_angles
  3. Seeds the gamepad’s joint targets to the home position
  4. Resets the selected joint to J1

If the robot’s config has no q_home_deg, the press is ignored with a warning in the Logs.

Multi-Robot

Each connected gamepad is assigned to one robot. By default, the first pad targets Robot 1, the second targets Robot 2 (following the active robot list). Press D-pad Left / Right to cycle the assignment at any time. The target robot can also be changed in Settings → Gamepad → Connected Controllers.

Plugging in a second controller mid-session automatically assigns it to the next available robot. Switching the target robot resets the pad’s joint and Cartesian targets, so they re-seed from the new robot’s live state before any command is sent — the previous robot’s targets are never replayed onto the new one.

Status Bar

The status bar shows the gamepad state next to the LED indicator:

JointJoint J1,J2 Medium | Impedance
CartesianCart XYZ+Yaw Fast | Planner

The text after the pipe is the last word of the mode name, so both Admittance Haptic modes display as | Haptic.

Settings

Open Settings → Gamepad to configure:

SettingDefaultDescription
Deadzone0.12Minimum stick deflection before input registers (0.0–0.5). Values above it are rescaled so output still ramps smoothly from 0 to full.
Axis InversionAll offCheckboxes to invert LX, LY, RX, RY individually
Button MappingKinova defaultsDropdown per button to assign any action

Settings are persisted to ~/.robot_selector_gui_settings.yaml under the gamepad key and take effect immediately.

The Connected Controllers list at the bottom of the tab shows a live card per pad with its device path, target-robot selector, current state, raw axis values and held buttons — useful for confirming which physical button corresponds to each label before remapping, and for diagnosing axis-direction issues.

* Gripper publishes only when the width has changed by ≥ 0.5% of full stroke since the last publish, so the effective rate depends on trigger deflection (at full deflection this works out to roughly every other 100 Hz tick).

Liveness gating

The 100 Hz publish loop only acts on a pad that has produced an input event within the last 0.75 s. A pad that goes silent (unplugged, or genuinely untouched) stops publishing immediately — targets are never streamed from a stale controller. Use the Topic Monitor to watch the command topics live.

Troubleshooting

SymptomCauseFix
No LED, no controller listed Permissions on /dev/input/js* Add user to input group: sudo usermod -aG input $USER, then log out/in
Sticks don’t move robot FIC controller not running Start the simulation or hardware controller first (see Quick Start)
Cartesian mode inactive, warning in log No live EE pose and no default_ee_target in the robot’s YAML config Start the controller so a live pose arrives, or add default_ee_target in Robot Configuration
Joint mode does nothing on first move No joint state feedback received yet — targets can’t be seeded Wait for joint state subscription, or start in Cartesian mode (default)
Axis direction feels wrong Controller variant maps axes differently Use the Axis Inversion checkboxes in Settings → Gamepad; the Connected Controllers card shows raw axis values live
Gripper doesn’t move Triggers not initialized (Xbox quirk) Pull and release both triggers once after plugging in
Robot jumps on mode switch Target re-seeding from live state Normal — the C++ controller snaps targets on mode change
